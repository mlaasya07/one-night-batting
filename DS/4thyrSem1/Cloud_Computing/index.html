⭐ 01 Cloud Computing — Definition & NIST Characteristics
▼
NIST Definition: Cloud computing is a model for enabling ubiquitous, convenient, on-demand network access to a shared pool of configurable computing resources (networks, servers, storage, applications, services) that can be rapidly provisioned and released with minimal management effort or service provider interaction.
On-demand Broad Network Access Resource Pooling Rapid Elasticity Measured Service Multi-tenant Pay-as-you-go

Five Essential Characteristics

1. On-demand Self-service

Users provision compute capabilities (storage, CPU) automatically without human interaction with the provider.

2. Broad Network Access

Capabilities available over the network, accessed via standard mechanisms — phones, tablets, laptops, workstations.

3. Resource Pooling

Provider pools resources to serve multiple consumers (multi-tenant). Physical and virtual resources are dynamically assigned.

4. Rapid Elasticity

Capabilities scale out/in rapidly (even automatically) to match demand. Appears unlimited to the consumer.

5. Measured Service

Resource usage is monitored, controlled, and reported (metered). Pay-per-use billing for storage, bandwidth, processing.

Write all 5 characteristics with one-line explanation each. Memory: O-B-R-R-M → "Orange Bears Really Run Marathons"

⭐ 04 Cloud Computing Architecture
▼
Cloud Architecture comprises multiple cloud components that are loosely coupled and connected through a network (usually the Internet). It is divided into two parts: Front End and Back End.
Front EndBack End HypervisorManagement SoftwareDeployment Software Loosely Coupled
Cloud Computing Architecture — Front End ↔ Internet ↔ Back End

Cloud Infrastructure Components

  • Hypervisor: Acts as Virtual Machine Manager; shares physical resources among tenants.
  • Management Software: Maintains and configures infrastructure.
  • Deployment Software: Deploys and integrates applications on the cloud.
  • Network: Connects cloud services; can be delivered as a utility over the Internet.
  • Server: Handles resource allocation, de-allocation, monitoring, and security.
  • Storage: Multiple replicas maintained; if one fails, extracted from another.
Keywords: Front End = User-facing. Back End = Cloud itself. Connected by Internet. Loosely coupled components.
⭐ 05 SOA as Technology Driver for Cloud Computing
▼
SOA (Service-Oriented Architecture) is an architectural framework where software applications are designed as a collection of modular, loosely coupled, and interoperable services. SOA served as the primary technical predecessor of cloud computing — the XaaS models (SaaS/PaaS/IaaS) directly inherit SOA's service-first principles.
Loose CouplingReusabilityInteroperability SOAPWSDLUDDIESBXMLREST

Core Technologies of SOA

TechnologyFull FormRole
XML / JSONExtensible Markup LanguageStandard data format for platform-independent exchange
WSDLWeb Services Description LanguageXML-based contract describing service capabilities and endpoints
SOAPSimple Object Access ProtocolStructured XML-based messaging with strict security
RESTRepresentational State TransferLightweight, URI-driven stateless Web API interactions
UDDIUniversal Description, Discovery, IntegrationCentralized lookup registry for publishing and discovering services
ESBEnterprise Service BusMiddleware for message routing, protocol translation, orchestration

Key Benefits of SOA

  • High Reusability: Services designed as autonomous units reused across multiple applications.
  • Loose Coupling: Internal changes don't affect dependent services (hidden behind contracts).
  • Interoperability: Uses SOAP/REST/HTTP to connect legacy apps with modern cloud systems.
  • Agility & Flexibility: Rapid service composition for quick response to business changes.
  • Location Transparency: Consumers access via registries without knowing physical server location.
  • Simplified Maintenance: Isolated boundaries allow independent updates without system downtime.

CCOA — Cloud-Centric SOA

CCOA synthesizes traditional SOA governance with elastic cloud capabilities. It enables multi-tenant service instances sharing elastic cloud infrastructure, supports real-time dynamic composition, and combines strict SOA governance with flexible cloud SLA management.

⭐ 06 Virtualization & Hypervisors
▼
Virtualization is the process of creating a virtual layer over physical hardware, allowing multiple virtual instances to run simultaneously on one physical machine. It is the key technology underlying cloud computing (Amazon EC2, VMware vCloud, etc.).
Full VirtualizationPara-VirtualizationHardware-assisted Type 1 HypervisorType 2 HypervisorVMwareKVM

Approaches to Virtualization

ApproachMechanismOverheadExample
Full VirtualizationBinary Translation + Direct Execution; completely abstracts physical hardwareHigh (translation overhead)VMware Workstation
Para-Virtualization (OS-assisted)Guest OS modified to use hypercalls instead of privileged instructionsMedium (modified guest)Xen Hypervisor
Hardware-assisted VirtualizationCPU vendor support (Intel VT-x, AMD-V) eliminates binary translation and hypercallsLow (hardware handles it)KVM, VMware ESXi

Types of Virtualization

  • Storage Virtualization: Multiple physical storages abstracted as multiple logical storage units.
  • Network Virtualization: Abstracting physical network components into a virtual network (e.g., AWS VPC).
  • Memory Virtualization: Virtual main memory provided to VMs abstracted from physical RAM.
  • Processor Virtualization: Physical CPU abstracted into a pool of virtual processors.
  • Application Virtualization: Users access centrally hosted apps virtually without installation (e.g., Citrix).
  • Data Virtualization: Unified logical view of data aggregated from heterogeneous sources without moving data.

Type 1 vs Type 2 Hypervisors

Type 1 (Bare-Metal) vs Type 2 (Hosted) Hypervisor Architecture
Type 1 = Directly on hardware → Cloud datacenters. Type 2 = On top of OS → Personal/Testing use.

Types of Cluster Computing

  • Load-Balancing Clusters: Distribute workload evenly across nodes.
  • High Availability (HA) Clusters: Redundant operation; if one node fails, another continues.
  • High Performance (HP) Clusters: Use supercomputers to solve advanced computation problems.

Types of Grid Computing

  • Computational Grid: Resources of many computers focused on one problem at a time.
  • Data Grid: Controlled sharing and management of large distributed data.
  • Collaborative Grid: Solves collaborative problems across organizations.
Grid = Cloud's predecessor. "Cloud computing is often referred to as the Successor of Grid Computing."

Web 2.0 Key Characteristics

  • User-Generated Content (UGC): Blogs, videos, posts, reviews (YouTube, Wikipedia, Medium).
  • Folksonomy & Tagging: Collaborative categorization via hashtags.
  • Rich User Experience: AJAX, DOM manipulation, Single-Page Applications (SPAs).
  • Cloud Synergy: Web 2.0 apps generate massive user spikes → cloud auto-scaling, S3 object storage.
  • SaaS Enabler: Established browser as OS → Google Docs, Figma, Salesforce.

Web 3.0 (Semantic Web) Architecture

Web 3.0 structures internet data into standardized, machine-readable formats using RDF, OWL, and SPARQL so machines understand context and entity relationships — from keyword matching ("strings") to concept understanding ("things").
  • RDF (Resource Description Framework): Represents data as Subject–Predicate–Object triples. e.g., (Amber) → (studies) → (Cloud Computing)
  • OWL (Ontologies): Defines precise domain logic and relationship rules.
  • SPARQL: Query language for RDF data.
  • Intelligent Agents: Autonomous programs executing complex query reasoning across systems.
  • Decentralization: Data moves from centralized servers to peer-to-peer ledger protocols (IPFS, Ethereum).
Web 3.0 + Cloud: IPFS/Ethereum need massive compute → cloud hyperscalers. Managed blockchain RPC nodes, AI model hosting, decentralized storage gateways.
⭐ 09 Multicore Technology & Parallelism in Cloud
▼
When single-core frequency scaling hit thermal power limits ("frequency wall"), processor vendors transitioned to placing multiple execution cores on a single physical die. Each core executes threads autonomously with L1/L2 caches; cores share L3 cache and memory controllers.
Task ParallelismData Parallelism SMPNUMAvCPUHypervisor MapReduceSpark

Types of Parallelism in Cloud

  • Task Parallelism: Large computations decomposed into discrete independent subtasks executed simultaneously across multiple CPU cores.
  • Data Parallelism: Massive datasets partitioned (MapReduce, Apache Spark) to execute identical operations on separate data chunks concurrently.
  • High Throughput: Simultaneously handling thousands of web requests, microservice API calls, and tenant workloads without I/O starvation.

Hypervisor & VM Scalability

  • Modern hypervisors (KVM, ESXi, Hyper-V) map virtual CPUs (vCPUs) directly to physical cores and hardware threads (Hyper-Threading).
  • Multicore architectures allow VMs to scale vertically by dynamically assigning 32+ vCPUs to heavy workloads like database engines.
  • NUMA (Non-Uniform Memory Access): Arranges cores and memory into local nodes to maximize bandwidth and minimize cross-socket latency.

Enterprise Deployments

  • AWS Graviton3 & AMD EPYC: 64–128 core CPUs powering compute-optimized instances (c7g, c6a).
  • Container Orchestration (Kubernetes): CPU pin allocation for microservices — prevents noisy-neighbor bottlenecks.
  • AI & Big Data: Multicore systems feed high-speed memory channels for parallel LLM inference and distributed SQL.
Why multicore → cloud? Scaling CPU density increases throughput near-linearly while drastically reducing server footprint and energy per virtual guest.

⭐ 12 Other Technology Drivers — Pervasive Computing & OS
▼
Pervasive Computing (Ubiquitous Computing): Computing embedded into everyday objects and environments — seamless access across IoT devices, edge nodes, AR/VR environments, and pervasive computing frameworks. Drives the need for cloud as the backbone infrastructure.
IoTEdge ComputingFog Computing UbiquitousAR/VRSensors

Pervasive Computing Characteristics

  • Ubiquity: Computing available everywhere — on phones, wearables, smart appliances.
  • Invisibility: Technology fades into background; users interact naturally.
  • Context-Awareness: Devices adapt behavior based on location, time, user identity.
  • Connectivity: Constant network connectivity (WiFi, 5G, Bluetooth).

Cloud as OS

Web 2.0 established the web browser as an operating system environment, enabling SaaS applications like Google Docs, Figma, and Salesforce where users access full-featured software without any local installation. The cloud OS concept extends this — resource management, scheduling, security all handled at cloud scale.
