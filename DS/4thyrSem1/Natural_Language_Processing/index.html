Unit 1 — Morphology & Morphological Parsing
A.1 State the meaning of Morphological Parsing and illustrate it with a suitable example. 2M
Morphological Parsing is the computational process of analyzing a word to decompose it into its constituent morphemes and determine its grammatical properties such as part of speech, tense, number, and gender.

The parser takes a surface word form as input and returns a structured description of its internal components.

Example:
Word: "unhappiness" un- → prefix meaning "not" (bound morpheme) happy → root/stem (free morpheme) -ness → suffix indicating "state of" (bound morpheme) Output: un + happy + ness → ADJ [negation + root + nominalization]
Morphological parsing is essential in NLP for tasks like machine translation, stemming, lemmatization, and information retrieval. A morphological parser produces a lexeme (base dictionary form) plus a set of morphosyntactic features (e.g., PLURAL, PAST) for every input token.

A.3 What is Morphology in Natural Language Processing? 2M
Morphology is the branch of linguistics that studies the internal structure and formation of words. In NLP, it refers to the computational analysis of how words are built from smaller meaningful units called morphemes.

Morphology in NLP encompasses:
  • Inflectional morphology — grammatical variations of the same word (run → runs, ran, running)
  • Derivational morphology — creating new words by adding affixes (teach → teacher → teachable)
  • Compounding — combining two roots (news + paper = newspaper)
NLP systems use morphological analysis as a preprocessing step to normalize word forms, reduce vocabulary size, and improve performance in tasks like text classification, machine translation, and speech recognition.

A.6 What is a Morph? Give a suitable example. 2M
A morph is the minimal phonological or orthographic unit that realizes a morpheme in actual language use. It is the concrete, visible or audible segment of a word corresponding to an abstract morpheme.

Example — English plural morpheme:
cat → cat + /s/ morph: -s (voiceless) dog → dog + /z/ morph: -z (voiced) bus → bus + /ɪz/ morph: -es (after sibilant) ox → ox + /ɛn/ morph: -en (irregular)
All four morphs (-s, -z, -es, -en) are realizations of the same PLURAL morpheme. The morph chosen depends on phonological context. When morphs of the same morpheme are analyzed, they are called allomorphs.

A.9 What is Morphological Analysis in NLP? 2M
Morphological Analysis in NLP is the process of examining a word to determine its constituent morphemes, its root/lemma form, and its morphosyntactic features (tense, number, gender, case, etc.).

It typically produces output in the form: word → lemma + [features]
Input: "running" Output: run + [VERB, PRESENT_PARTICIPLE, PROGRESSIVE] Input: "children" Output: child + [NOUN, PLURAL] Input: "happiest" Output: happy + [ADJ, SUPERLATIVE]
Morphological analysis is the foundation for higher NLP tasks: it feeds into POS tagging, parsing, machine translation, and information extraction by normalizing word forms and making grammatical information explicit.
A.10 State the importance of Morphological Analysis in Natural Language Processing. 2M
Morphological analysis is critically important in NLP for the following reasons:
  • Vocabulary reduction — maps inflected forms to a single root, reducing data sparsity
  • Lemmatization & stemming — normalizes "runs", "ran", "running" → "run"
  • Machine translation — generates correct target-language inflections
  • POS tagging — morphological features help assign part-of-speech labels
  • Morphologically rich languages — essential for Arabic, Turkish, Finnish where a single word can encode an entire sentence
  • Search engines — expands queries to match all word forms
  • Chatbots & spell-checkers — understand variant word forms
Without morphological analysis, NLP systems would treat "walk", "walks", "walked", and "walking" as four completely unrelated tokens.

A.12 What are the major components of Morphological Parsing? 2M
The major components of a morphological parser are:
  • Lexicon / Dictionary — stores root words and their grammatical properties
  • Morphological Rules — describes how affixes combine with roots (e.g., suffix -ed → PAST)
  • Finite-State Transducer (FST) — encodes spelling alternations between surface forms and lexical forms
  • Tokenizer — splits input text into tokens before analysis
  • Segmentation Module — identifies morpheme boundaries within a word
  • Feature Extractor — assigns grammatical feature values (TENSE, NUMBER, GENDER)
  • Ambiguity Resolver — selects the most likely analysis when multiple parses are possible
Together these components transform raw word forms into structured morphosyntactic representations.

A.18 What is meant by representing related word forms under a single dictionary entry? 2M
A dictionary groups all inflected and variant forms of a word under one headword (the lemma) rather than listing each form separately. This concept is called lexical consolidation or lemma-based organization.

For example, a dictionary has a single entry for the verb receive, which covers: receive, receives, received, receiving, receiver, reception. All these forms share the same core meaning and are semantically related.

In NLP, this principle is operationalized as lemmatization — the process of mapping every surface word form to its lemma, so that "was", "is", "are", "been" all reduce to the single lemma "be". This dramatically reduces vocabulary size and improves performance in tasks like text classification and information retrieval.

Sentence Segmentation & Boundary Detection
A.20 What is Sentence Boundary Detection? 2M
Sentence Boundary Detection (SBD), also called sentence segmentation, is the NLP task of automatically identifying where one sentence ends and the next begins in a stream of text or speech.

The challenge is distinguishing between end-of-sentence punctuation and other uses of the same characters:
Ambiguous: "Dr. Smith arrived at 10 a.m. He left early." Periods at: "Dr." "a.m." ← NOT sentence boundaries "early." ← IS a sentence boundary
SBD is typically the first preprocessing step in an NLP pipeline — downstream tasks (parsing, translation, summarization) all assume correctly identified sentence units as input. Methods range from hand-written rules to supervised classifiers using features around punctuation marks.
A.21 State the purpose of Sentence Segmentation in Natural Language Processing. 2M
The primary purpose of sentence segmentation is to split a continuous stream of text into discrete, meaningful sentence units so that downstream NLP processes can operate on them correctly.

Specific purposes:
  • Machine Translation — translates sentence by sentence
  • Parsing — syntactic parsers require sentence-level input
  • Summarization — selects the most informative sentences
  • Information Extraction — identifies entities and relations within sentences
  • Sentiment Analysis — assigns sentiment to individual sentences
  • Speech Recognition — segments spoken transcripts into utterances
Without sentence segmentation, a 1000-word paragraph would be treated as a single unit, breaking virtually every downstream task.
A.22 Why is sentence segmentation considered an important preprocessing step in NLP? 2M
Sentence segmentation is the entry point of most NLP pipelines — nearly every higher-level task assumes sentences as input units. Its importance stems from:
  • Foundation for parsing — CFGs and dependency parsers operate on single sentences
  • Unit of analysis — Semantics, co-reference resolution, and NER all work at sentence level
  • Training data quality — ML models trained on incorrectly segmented text learn wrong patterns
  • Cross-lingual NLP — Different languages have very different sentence-boundary conventions
  • Speech processing — Spoken language lacks explicit punctuation; SBD must infer from prosody
An error in sentence boundary detection propagates through the entire pipeline — a misidentified boundary corrupts every subsequent analysis.

A.24 How do punctuation marks help in sentence segmentation? 2M
Punctuation marks are the primary surface-level cues for sentence boundary detection, though they require contextual interpretation:

End-of-sentence signals: Period (.), Question mark (?), Exclamation mark (!), followed by a capital letter and whitespace — these together form the strongest heuristic for a sentence boundary.

Non-sentence-boundary uses: The same period appears in abbreviations (Dr., Mr., U.S.), decimals (3.14), URLs (google.com), and initials (J.R.R. Tolkien).

Practical systems use a combination of:
  • Abbreviation lists — precompiled list of known abbreviations to filter
  • Capitalization of the next word — strong boundary signal
  • Word length before period — short words (2–3 chars) more likely abbreviations
  • Contextual classifiers — ML models trained on labeled data
A.25 Explain the problem of abbreviations in sentence boundary detection with an example. 2M
Abbreviations are the hardest challenge in sentence boundary detection because they use the same period character as sentence terminators, creating systematic ambiguity.

Example:
Text: "Dr. Ramesh arrived at 10 a.m. He attended the meeting." Period analysis: "Dr." → abbreviation (NOT a sentence boundary) "a.m." → abbreviation (NOT a sentence boundary) "meeting." → REAL sentence boundary A naive period-based splitter would incorrectly create 3 "sentences": [1] "Dr." [2] "Ramesh arrived at 10 a.m." [3] "He attended the meeting."
Solutions include abbreviation dictionaries, context features (capitalization of next word, word preceding period), and ML classifiers that learn to distinguish boundary vs. abbreviation periods from training data.
Unit 2 — Parsing & Syntactic Analysis
A.26 What is Parsing in Natural Language Processing? 2M
Parsing in NLP is the process of analyzing a sentence to uncover its hidden grammatical structure — determining how words group together into phrases and how phrases relate to each other. A parser takes a sentence as input and produces a parse tree or dependency graph as output.

Input: "The dog chased the cat." Output: [S [NP [Det The] [N dog]] [VP [V chased] [NP [Det the] [N cat]]]]
Parsing varies from shallow (POS tagging only) to deep (full predicate-argument structure). It uses knowledge encoded in a grammar (CFG, PCFG) or learned from annotated treebanks to find the most probable structural analysis consistent with the grammar and the input.
A.27 Discuss the importance of Parsing with a suitable example. 2M
Parsing is fundamental to NLP because it reveals the latent grammatical relationships that give sentences their meaning. Without parsing, sentences that look identical on the surface are indistinguishable despite having completely different meanings.

Classic example of why parsing matters:
Sentence: "I saw the man with a telescope." Parse 1: [I] [saw [the man with a telescope]] → The man has a telescope. (PP modifies "the man") Parse 2: [I] [saw [the man] [with a telescope]] → I used a telescope to see the man. (PP modifies "saw")
Parsing also enables paraphrasing, question answering, machine translation, and information extraction. A sentence like "He wanted to go for a drive in the country" has a natural pause before "in" that only parsing can make explicit.
A.28 What is a Parse Tree? 2M
A parse tree (also called a syntax tree or phrase structure tree) is a hierarchical tree-structured representation of the syntactic structure of a sentence according to a grammar. It shows how words group into phrases and how phrases nest within each other.
Parse Tree — "The dog chased the cat"
Leaf nodes are words (terminals); internal nodes are non-terminals (S, NP, VP, etc.) representing grammatical categories.
A.29 What is Syntactic Parsing? 2M
Syntactic Parsing is the process of analyzing a sentence's grammatical structure to determine how its words are related through syntactic rules. It uncovers the hierarchical organization of a sentence into phrases (constituents) and the head-dependent relationships between words.

Two main forms:
  • Constituency/Phrase-Structure Parsing — groups words into nested phrases (NP, VP, PP) using a grammar like CFG
  • Dependency Parsing — identifies directed relationships (head → dependent) between words
Syntactic parsing is critical for downstream semantic tasks — you cannot determine "who did what to whom" without knowing the subject, verb, and object of a sentence, which syntactic parsing provides.
A.30 Define a Context-Free Grammar (CFG). 2M
A Context-Free Grammar (CFG) is a formal grammar consisting of a set of production rules that describe how to generate the sentences of a language. It is "context-free" because the left-hand side of every rule is a single non-terminal symbol — its expansion does not depend on surrounding context.

Formal definition: A CFG G = (V, Σ, R, S) where V = non-terminals, Σ = terminals, R = production rules, S = start symbol.
Sample CFG for English: S → NP VP NP → Det N | NP PP VP → V NP | VP PP PP → P NP Det → "the" | "a" N → "dog" | "cat" | "man" V → "chased" | "saw" P → "with" | "in"
CFGs are the standard grammatical formalism used in constituency parsing. They allow systematic enumeration of all grammatically valid sentence structures.
A.31 What are the basic components of a Context-Free Grammar? 2M
A CFG has exactly four components:

A.32 What is syntactic ambiguity? Give a suitable example. 2M
Syntactic ambiguity occurs when a sentence has more than one grammatically valid parse tree — i.e., when the same sequence of words can be structured in multiple ways, yielding different meanings.

Classic example:
"I saw the man with a telescope." Parse A: I [saw [the man with a telescope]] → "the man" has a telescope (PP attaches to NP) Parse B: I [saw [the man] [with a telescope]] → I used a telescope (PP attaches to VP)
Another example: "Flying planes can be dangerous" — either planes that fly are dangerous, or the act of flying planes is dangerous.

Syntactic ambiguity is extremely common in natural language and is one of the primary reasons parsers use probabilistic models (PCFGs) to select the most likely interpretation.

A.34 What is Constituency Parsing? 2M
Constituency Parsing (also called phrase structure parsing) is the process of analyzing a sentence by grouping words into nested constituents (phrases) based on a grammar. Each constituent is a natural linguistic unit — NP, VP, PP, etc. — that can be replaced by a single pronoun.

Sentence: "The student reads a book." Constituents: [NP The student] [VP reads [NP a book]] └→ Full parse: [S [NP The student] [VP reads [NP a book]]]
The output is a parse tree where leaf nodes are words and internal nodes are phrase labels. Constituency parsing is based on CFGs or PCFGs and is used in applications like machine translation, paraphrase detection, and semantic role labeling.
A.35 What is Dependency Parsing? 2M
Dependency Parsing analyzes a sentence by identifying directed binary relationships (dependencies) between words. Each word, except the root, depends on exactly one other word (its head). The result is a dependency tree or graph — no phrase nodes, only words connected by labeled arcs.

Sentence: "John loves Mary." Dependency tree: loves ← root John ← nsubj(loves) [John is subject of loves] Mary ← obj(loves) [Mary is object of loves]
Common dependency relation labels: nsubj (nominal subject), obj (direct object), det (determiner), amod (adjectival modifier). Dependency parsing is preferred for free word-order languages (Turkish, Czech, Hindi) where constituency analysis is difficult.

Parsing Models & Algorithms
A.38 What are Generative Models for Parsing? 2M
Generative models for parsing define a joint probability distribution P(sentence, parse tree). They model how sentences are generated from a probabilistic grammar. Given a sentence, the parser selects the parse tree that maximizes this joint probability.

Key characteristic: They model P(x, y) — the probability of both the observation (sentence) and the label (parse tree) — then use Bayes' rule to find P(y|x).

Primary example: Probabilistic Context-Free Grammar (PCFG) — each CFG rule A → α has an attached probability P(A → α). The probability of a parse tree is the product of all rule probabilities used.

Generative models are efficient to train (maximum likelihood estimation) and handle large training sets well, but their conditional distribution P(y|x) is implicit and they use a limited feature set.
A.39 What are Discriminative Models for Parsing? 2M
Discriminative models for parsing directly model the conditional probability P(parse tree | sentence) — the probability of a parse given the observed input, without modeling how the sentence was generated.

They optimize classification: given a sentence and a set of candidate parses, pick the highest-scoring one using a rich feature set that can include arbitrary properties of the sentence and parse.

Examples: Maximum Entropy (log-linear) models, Support Vector Machines (SVMs), Conditional Random Fields (CRFs), Neural networks.

Advantages: Can incorporate overlapping features, achieve higher accuracy on smaller datasets, and are not constrained by generative assumptions.

Disadvantage: Require iterative training, are slower to train, and can overfit on small datasets.
A.40 State the basic characteristics of Discriminative Models for Parsing. 2M
  • Model P(y|x) directly — no assumptions about how the input x was generated
  • Rich feature sets — can use any feature of the sentence or candidate parse (n-grams, POS tags, distances, word embeddings)
  • No independence assumptions — features may overlap and correlate freely
  • Discriminative training — optimized by maximizing classification margin or log-likelihood of correct parses
  • Better accuracy — consistently outperform generative models on standard benchmarks
  • Higher training cost — require multiple passes over training data to converge
  • Require decoding — use Viterbi or beam search to find the best parse at test time
Modern neural parsers (e.g., BiLSTM + attention) are discriminative models that have achieved state-of-the-art performance on English and multilingual parsing benchmarks.

A.42 What is a Probabilistic Context-Free Grammar (PCFG)? 2M
A Probabilistic Context-Free Grammar (PCFG) is a CFG where each production rule A → α is assigned a probability P(A → α), representing the probability that the non-terminal A expands to α. Probabilities of all rules with the same left-hand side must sum to 1.

PCFG example: S → NP VP [1.0] NP → Det N [0.6] NP → NP PP [0.4] VP → V NP [0.7] VP → VP PP [0.3] Parse tree probability = PRODUCT of all rule probabilities used e.g., P(tree) = 1.0 × 0.6 × 0.7 × 0.6 = 0.252
PCFGs enable disambiguation: when a sentence has multiple parses, the parser selects the one with the highest probability. Rule probabilities are estimated from a treebank using maximum likelihood estimation.
A.43 State the importance of PCFGs in Natural Language Processing. 2M
PCFGs are important in NLP for the following reasons:
  • Ambiguity resolution — assigns probabilities to competing parse trees; highest-probability tree is selected
  • Data-driven — probabilities learned from annotated treebanks, not hand-coded
  • Principled probabilistic framework — allows Bayesian reasoning and use of expectation-maximization
  • Efficiency — CYK algorithm finds the best parse in O(n³) time using PCFG probabilities
  • Machine translation — synchronous PCFGs model translation as probabilistic grammar transformation
  • Unsupervised grammar induction — PCFGs can be estimated from unannotated text using EM
PCFGs extended the pure CFG framework into a learnable, probabilistic model, making syntactic parsing a statistical estimation problem.
A.44 How does a PCFG help in resolving syntactic ambiguity? 2M
A PCFG resolves syntactic ambiguity by assigning a probability score to every possible parse tree and selecting the highest-probability tree as the output — the Viterbi parse.

Example — PP Attachment ambiguity:
"I saw the man with a telescope." Parse A: NP[man] PP[with telescope] Uses: NP → NP PP [prob 0.4] Parse A probability: ... × 0.4 = 0.18 Parse B: VP[saw] PP[with telescope] Uses: VP → VP PP [prob 0.3] Parse B probability: ... × 0.3 = 0.12 PCFG selects Parse A (higher probability)
The probabilities encode corpus-derived knowledge about how frequently different attachment choices occur in real text. When training data is large enough, the PCFG learns to prefer the linguistically more natural reading.
A.45 What is Top-Down Parsing? 2M
Top-Down Parsing starts from the start symbol S of the grammar and applies production rules to expand non-terminals, working downward toward the terminal symbols (words) of the input sentence. It attempts to predict what the sentence should look like according to the grammar.

Grammar: S → NP VP, NP → Det N, VP → V NP Input: "The cat sat" Top-down derivation: S → NP VP (expand S) → Det N VP (expand NP) → "The" N VP (match "The") → "The" "cat" VP (match "cat") → "The" "cat" V NP (expand VP) → "The" "cat" "sat" NP (match "sat") ...
Top-down parsers can waste time exploring grammar rules that don't match the input. They may get stuck in left recursion (S → S NP cycles infinitely).
A.46 What is Bottom-Up Parsing? 2M
Bottom-Up Parsing starts with the input words (terminals) and applies grammar rules in reverse — reducing groups of terminals and non-terminals to larger non-terminals — until the start symbol S is derived. It is data-driven: it only builds structures actually present in the input.

Input: "The cat sat" Rules: Det → "The", N → "cat", V → "sat", NP → Det N, VP → V, S → NP VP Bottom-up derivation: "The" "cat" "sat" → Det "cat" "sat" (reduce "The" to Det) → Det N "sat" (reduce "cat" to N) → NP "sat" (reduce Det N to NP) → NP V (reduce "sat" to V) → NP VP (reduce V to VP) → S (reduce NP VP to S) ✓
Bottom-up parsers cannot get stuck in left recursion and only build grammatically valid sub-structures. Used in Shift-Reduce parsers.

A.48 What is Chart Parsing? 2M
Chart Parsing (also called well-formed substring table parsing) is a dynamic programming parsing technique that avoids redundant computation by storing all partial parse results in a data structure called a chart. Once a constituent spanning a particular range of words is found, it is stored and reused rather than recomputed.

The chart is a triangular table where entry [i,j] stores all non-terminals that span words i through j. Both top-down and bottom-up strategies can be implemented as chart parsers.

Earley's algorithm is the classic chart parser — it processes left-to-right, maintains items (dotted rules showing progress), and can handle any CFG including ambiguous and left-recursive grammars in O(n³) time. Chart parsing is the foundation of modern treebank parsers.
A.49 What is Shift-Reduce Parsing? 2M
Shift-Reduce Parsing is a bottom-up parsing strategy that uses a stack and an input buffer. At each step, the parser chooses between two operations:
  • Shift — move the next word from the buffer onto the stack
  • Reduce — if the top k items on the stack match the right-hand side of a grammar rule A → α, replace them with A
Parsing succeeds when the entire input is consumed and the stack contains only S.

Input: "a and b" Stack Buffer Action [] a and b Shift [a] and b Reduce: N → a [N] and b Shift [N, and] b Shift [N,and,b] [] Reduce: N → b [N,and,N] [] Reduce: S → N and N ✓
Shift-Reduce allows linear-time parsing but may require backtracking in the worst case (O(n³)).
A.50 What is the CYK Algorithm? 2M
The Cocke-Younger-Kasami (CYK) algorithm is a dynamic programming bottom-up parsing algorithm that works on CFGs in Chomsky Normal Form (CNF) — where every rule is either A → BC (two non-terminals) or A → w (one terminal).

It fills a triangular parse table bottom-up, computing which non-terminals can span each substring of the input:
For input of length n, table has O(n²) cells. Each cell [i,j] stores non-terminals spanning positions i to j. Time complexity: O(n³ × |G|) Space complexity: O(n²) Base case: [i, i+1] ← {A | A → word_i exists in grammar} Recursive: [i, j] ← {A | A → BC, B ∈ [i,k], C ∈ [k,j] for some k}
CYK guarantees finding all valid parse trees in polynomial time and is the basis of the CKY hypergraph parser for PCFGs.
A.51 What is Earley's Parsing Algorithm? 2M
Earley's Algorithm is a chart-based, top-down parsing algorithm that can handle any CFG — including ambiguous, left-recursive, and nullable grammars — in O(n³) time (O(n²) for unambiguous grammars, O(n) for grammars with finite ambiguity).

It processes the input left-to-right and maintains Earley items (dotted rules) of the form [A → α • β, i, j] — meaning "we've parsed α from position i to j, and still need to parse β to complete A".

Three operations:
  • Predict — when a dot precedes a non-terminal, add items for all rules for that non-terminal
  • Scan — when a dot precedes a terminal matching the next word, advance the dot
  • Complete — when a rule is fully matched, advance the dot in all items waiting for it
Earley's algorithm is the most general and elegant parsing algorithm for context-free grammars.

B.1 Discuss the meaning, process, and importance of Morphological Parsing with suitable examples. 5M

Definition: Morphological Parsing is the computational process of analyzing a word to identify its constituent morphemes and determine its lexical and grammatical properties. The goal is to map from a surface form (the word as written) to a lexical form (root + grammatical features).

The Process of Morphological Parsing

The parsing pipeline involves five stages:

  1. Tokenization — split input text into individual word tokens
  2. Segmentation — identify morpheme boundaries within each token
  3. Identification — classify each segment as root, prefix, suffix, or infix
  4. Analysis — assign morphosyntactic features to each morpheme
  5. Disambiguation — if multiple analyses exist, select the most likely one
Example: "unhappiness" Step 1: un + happy + ness Step 2: un- (prefix: negation), happy (root: ADJ), -ness (suffix: nominalization) Step 3: Lexical form: UN + HAPPY + NESS → [NOUN, NEGATIVE, STATE] Output: {lemma: "happy", POS: NOUN, prefix: NEG, nominalization: +NESS} Example: "replayed" re- (prefix: again), play (root: VERB), -ed (suffix: PAST) Output: {lemma: "play", POS: VERB, TENSE: PAST, ASPECT: repetition}

B.2 Discuss the issues and challenges associated with Morphological Parsing. 5M

Morphological parsing faces three fundamental challenges that make it a non-trivial computational problem: irregularity, ambiguity, and productivity.

1. Irregularity

Many words deviate from regular morphological patterns. Rule-based parsers that work for regular forms fail on irregular ones, which must be stored individually in a lexicon.

2. Ambiguity

A single surface word form may correspond to multiple valid morphological analyses, requiring contextual disambiguation:

"saw" → {lemma: see, PAST TENSE} OR {lemma: saw, NOUN (tool)} "flies" → {lemma: fly, VERB, 3SG} OR {lemma: fly, NOUN, PLURAL} "wound" → {lemma: wind, PAST} OR {lemma: wound, NOUN}

A morphological parser must use surrounding context (POS tags, syntactic constraints) to resolve such ambiguities. Ambiguity rate is especially high in languages with rich homophony.

3. Productivity / Unknown Words

Languages continuously generate new words through affixation, compounding, and conversion. A parser trained on a static lexicon will encounter OOV (out-of-vocabulary) words it has never seen:

New words: "googling", "unfriended", "tweeted", "selfie-ready" Morphological rules required: google + -ing → [VERB, PRESENT_PARTICIPLE] un- + friend + -ed → [VERB, PAST, NEGATIVE]

4. Morphologically Rich Languages

Languages like Turkish, Finnish, Arabic, or Sanskrit can produce thousands of inflected forms for a single root. A Turkish verb stem can have over 3,000 valid surface forms. The lexicon size required for these languages makes pure dictionary lookup infeasible.

5. Allomorphy

Multiple surface forms (allomorphs) encode the same morpheme. The negation prefix in- has allomorphs in-, im-, il-, ir- (incapable, impossible, illegal, irregular) — a parser must recognize all as realizations of the same abstract morpheme.

Real-world morphological parsers address these challenges through a combination of finite-state transducers for regular patterns, lexicons for irregular forms, and machine learning for unknown word handling.

B.3 Explain the different types of Morphemes with suitable examples. 5M

Morphemes are classified along two primary dimensions: whether they can stand alone (free vs. bound) and what grammatical function they serve (derivational vs. inflectional).

1. Free Morphemes

Free morphemes can stand alone as independent words. They are further divided into:

  • Lexical morphemes — content words carrying semantic meaning: dog, run, happy, blue
  • Functional morphemes — grammatical words with structural role: the, and, but, of, to

2. Bound Morphemes

Bound morphemes cannot stand alone; they must attach to a root or stem. They include:

  • Prefixes — attached before the root: un-, re-, pre-, dis-
  • Suffixes — attached after the root: -ness, -ed, -ing, -er, -tion
  • Infixes — inserted within a root (rare in English, common in Tagalog)
  • Circumfixes — wrap around the root (e.g., German ge-...-t for past participle)

3. Inflectional Morphemes

Inflectional morphemes modify a word's grammatical category without creating a new word or changing its core meaning:

Understanding morpheme types is fundamental to morphological analysis — NLP systems must identify and categorize each morpheme to correctly determine a word's grammatical properties and semantic contribution to a sentence.

B.4 Explain Inflectional and Derivational Morphology with suitable examples. 5M

Morphology is broadly divided into two types based on the role of affixes: inflectional morphology (grammatical variation of the same word) and derivational morphology (creating new words with new meanings).

Inflectional morphology deals with grammatical modifications of a word that are required by syntactic context. The word's core meaning and part of speech do not change; only grammatical categories like tense, number, case, person, aspect, and degree change.

  • Does not create a new word — "runs" is still the verb RUN

B.5 Discuss Morph, Morpheme, and Allomorph in detail with suitable examples. 5M

Three foundational concepts in morphology — morpheme, morph, and allomorph — exist at different levels of abstraction and are related as: morpheme (abstract) → morph (concrete instance) → allomorph (variant morph of the same morpheme).

Morpheme

A morpheme is the smallest abstract linguistic unit that carries meaning. It exists at the level of the language system (langue), not at the level of actual utterances (parole). Morphemes are represented in SMALL CAPS as conceptual units.

  • PLURAL — the abstract concept of "more than one"
  • PAST — the abstract concept of past tense
  • NEGATION — the abstract concept of negating a property

A morpheme is identified by its meaning or grammatical function, not by its sound or spelling.

Morph

A morph is the minimal phonological or graphemic unit that realizes a morpheme in actual speech or text — it is the observable, physical form. Every time a morpheme appears in a word, it appears as a specific morph.

The PLURAL morpheme appears as: -s in "cats" (a morph) -es in "buses" (a morph) -en in "oxen" (a morph) -i in "cacti" (a morph) -∅ in "sheep" (zero morph — no overt form)

Allomorphs

Allomorphs are different morphs that realize the same morpheme. They have identical meaning/function but different phonological forms, distributed in complementary environments.

Allomorph normalization is a critical step in morphological analysis for multilingual NLP systems.

B.6 Explain the process of Morphological Analysis in Natural Language Processing. 5M

Morphological analysis is the systematic computational process of decomposing word tokens into their constituent morphemes and extracting grammatical features. It is the first and most fundamental preprocessing step in any NLP pipeline.

Stage 1: Tokenization

Before morphological analysis, the input text must be tokenized — split into word-level units. This is itself non-trivial: contractions ("won't" → "will" + "not"), hyphenated compounds, and clitics all require special handling.

Stage 2: Segmentation

The tokenized word is segmented into morphemes by identifying the stem/root and any affixes:

Input: "internationalization" Segmentation: inter- + nation + -al + -iz + -ation inter- : prefix (between) nation : root (N) -al : suffix (Adj-forming) -iz : suffix (V-forming) -ation : suffix (N-forming, nominalization)

Stage 3: Lexical Lookup

The identified root is looked up in a morphological lexicon to retrieve its base properties (POS, semantic class, irregular forms). For regular words, morphological rules generate the analysis; for irregular words, the lexicon stores the mapping.

Stage 4: Feature Extraction

Grammatical features are extracted from the identified morphemes and assembled into a feature structure:

WordLemmaPOSFeatures
walkedwalkVERB[PAST, REGULAR]
childrenchildNOUN[PLURAL, IRREGULAR]
happiesthappyADJ[SUPERLATIVE]

Stage 5: Disambiguation

Many words have multiple valid morphological analyses. The disambiguation stage selects the correct analysis based on context — using surrounding POS tags, syntactic constraints, or a language model:

"saw" — context "she saw a bird" → {VERB, PAST(SEE)} "saw" — context "a saw and a hammer" → {NOUN, SINGULAR(SAW)}

Morphological Models Used

NLP systems implement morphological analysis using one or more models:

  • Dictionary Lookup — stores all forms; fast but can't handle OOV
  • Finite-State Transducer (FST) — encodes morphological rules as state machines; efficient and handles regular patterns
  • Unification-Based — uses feature structures; handles complex agreement
  • Machine Learning — neural sequence models that learn morphological mappings from data

The output of morphological analysis — lemma + feature values — feeds directly into POS tagging, syntactic parsing, machine translation, and semantic analysis, making it indispensable to the entire NLP pipeline.

B.7 Discuss the role of Morphological Parsing in NLP applications. 5M

Morphological parsing plays a foundational role across virtually every NLP application by normalizing word forms, extracting grammatical information, and reducing vocabulary complexity.

1. Machine Translation (MT)

MT systems must generate grammatically correct target-language sentences. Morphological parsing analyzes source-language words for tense, number, and case; the generation module then applies target-language morphological rules to produce the correct inflected output. For example, translating "he runs" to Spanish requires knowing VERB + 3SG to generate "él corre" rather than "él correr".

2. Information Retrieval (Search Engines)

Search queries are morphologically analyzed so that "running shoes" matches documents containing "run", "runs", or "runner". Without morphological normalization, each inflected form would be indexed separately, causing recall failures. Stemming and lemmatization are the primary morphological tools used in IR.

3. Chatbots and Virtual Assistants

Chatbots must understand user input regardless of grammatical variation. Morphological parsing allows "Did he went?" to be understood despite the grammatical error, by extracting the PAST tense intent from "went".

4. Sentiment Analysis

Negation morphemes (un-, dis-, -less) directly affect sentiment polarity. "unhappy" has opposite sentiment to "happy"; "hopeless" negates hope. Morphological parsing identifies negation prefixes that invert sentiment, which is crucial for accurate sentiment classification.

5. Named Entity Recognition (NER)

In morphologically rich languages, entity names are inflected for case. "Germany" in German appears as Deutschland (nominative), Deutschlands (genitive), Deutschland (dative). A morphological parser normalizes these to the base form for entity matching.

6. Speech Recognition

Language models used in speech recognition are morphology-aware — they can better predict the next word based on the morphological form of the current word (e.g., a plural noun is more likely to be followed by a plural verb).

B.8 Explain the challenges involved in morphological analysis of morphologically rich languages. 5M

Morphologically rich languages (MRLs) — such as Turkish, Arabic, Finnish, Sanskrit, Czech, and Telugu — present dramatically greater challenges for morphological analysis than analytic languages like English. In MRLs, a single word form can express the semantic content of an entire English clause.

1. Extreme Form Proliferation

Turkish, a highly agglutinative language, can produce tens of thousands of grammatically valid word forms from a single root. The verb "gelmek" (to come) can combine with tense, aspect, modality, negation, and subject agreement to produce thousands of forms:

geliyorum = I am coming gelmiyordum = I was not coming gelemeyecektim = I would not have been able to come gelemeyebilirim = I may not be able to come

A parser must handle all valid combinations without enumerating them individually.

2. High Ambiguity Rate

Arabic words are written without short vowels (diacritics), leading to extreme lexical and morphological ambiguity. A single unvocalized Arabic word string can correspond to dozens of different analyses depending on the intended vowels and morphological structure.

3. Non-concatenative Morphology

Semitic languages (Arabic, Hebrew) use root-and-pattern morphology — the root is a sequence of consonants (usually 3), and grammatical meaning is conveyed by changing the intervening vowel pattern:

Arabic root k-t-b (related to "writing"): kataba = he wrote kitaab = book kaatib = writer maktaba = library maktub = written

This non-concatenative structure cannot be analyzed by simple prefix/suffix rules — it requires special morphological formalisms.

4. Large Lexicon Requirements

MRL parsers need much larger lexicons than English parsers. Finite-state transducers (FSTs) for Arabic morphology have hundreds of thousands of states and transitions. Building and maintaining these resources requires extensive linguistic expertise and time.

5. Code-Switching and Dialectal Variation

Many MRLs have multiple dialects with different morphological patterns. Egyptian Arabic, Moroccan Arabic, and Modern Standard Arabic all have different morphological rules. NLP systems built for one dialect often fail badly on another.

6. Data Sparsity

Statistical NLP models require large amounts of annotated training data. For MRLs, even moderate-sized corpora may not cover the full morphological space, leading to data sparsity problems that hurt model performance.

B.9 A dictionary represents related word forms under a single basic entry. Describe the concept of a Lexeme and illustrate it with suitable examples. 5M

A lexeme is the fundamental abstract unit of the vocabulary — a single conceptual entry in the mental lexicon that encompasses all morphologically related word forms sharing the same core meaning. The dictionary does not list "run", "runs", "ran", "running", and "runnable" as five separate entries; it groups them all under the single lexeme RUN.

  • Tokens — each occurrence of a word form in text

  • Lexical resources — WordNet, PropBank, FrameNet all use lemmas/lexemes as their organizing units
Sentence Boundary Detection
B.13 State the purpose of Sentence Boundary Detection (Sentence Segmentation) in NLP. Explain with suitable examples. 5M

Sentence Boundary Detection (SBD) — also called sentence segmentation — is the task of automatically identifying where one sentence ends and the next begins in a continuous stream of text or speech. It is the essential preprocessing step that transforms raw text into the sentence units required by downstream NLP systems.

Purpose and Necessity

Almost all NLP tasks operate on individual sentences: parsers parse sentences, translators translate sentences, summarizers select sentences. Without SBD, a multi-sentence paragraph would be fed as a single unit, corrupting every subsequent analysis.

How Sentence Boundaries Are Identified

In formal written English, sentences typically end with a period (.), question mark (?), or exclamation mark (!), followed by whitespace and a capitalized next word. This heuristic works well in clean text but fails in many real-world scenarios.

Example 1 — Simple Case

Input: "The cat sat on the mat. The dog barked loudly!" SBD correctly identifies two boundaries: Sentence 1: "The cat sat on the mat." Sentence 2: "The dog barked loudly!"

Example 2 — Abbreviation Challenge

Input: "Dr. Ramesh arrived at 10 a.m. He attended the meeting." Naive rule (period + capital = boundary) produces 3 sentences: ❌ "Dr." | "Ramesh arrived at 10 a.m." | "He attended the meeting." Correct SBD produces 2 sentences: ✓ "Dr. Ramesh arrived at 10 a.m." | "He attended the meeting."

Applications of Sentence Segmentation

NLP ApplicationWhy SBD is Needed

Methods for SBD

  • Rule-based — hand-written rules using abbreviation lists and capitalization heuristics
  • Generative (HMM) — models punctuation as a sequence labeling problem; uses Viterbi decoding to find the best boundary sequence
  • Discriminative (MaxEnt, SVM, CRF) — classifies each punctuation mark as boundary or non-boundary using rich feature sets
  • Hybrid — combines discriminative classifiers with HMM decoding for best of both approaches

Sentence segmentation seems simple but achieves only ~95-98% accuracy even with the best models, because the remaining 2-5% involve edge cases (code-switching, social media text, spoken transcripts) that defy systematic rules.

B.14 Discuss the issues and challenges involved in Sentence Segmentation. 5M

Sentence segmentation appears deceptively simple — find the period and split. But natural language presents numerous challenging situations where this fails, and a robust SBD system must handle all of them.

Challenge 1: Abbreviations

The most pervasive challenge. Periods in abbreviations look identical to sentence-terminating periods but are not boundaries:

Dr., Mr., Mrs., Prof. — title abbreviations U.S.A., U.K., E.U. — country/organization abbreviations a.m., p.m., etc., e.g. — Latin abbreviations Jan., Feb., Mar. — month abbreviations Apt., Blvd., Ave. — address abbreviations

The problem is especially hard when an abbreviation appears at the end of a sentence: "She arrived at 5 p.m. He left at 6." — the period after "p.m." is both abbreviation-terminal AND sentence-terminal.

Challenge 2: Proper Nouns and Initials

Personal names with initials create false boundaries: "J.K. Rowling wrote Harry Potter." — the periods after "J" and "K" are not boundaries. Geographic and institutional names also cause problems: "U.N. Secretary-General spoke today."

Challenge 3: Quoted Speech / Nested Sentences

She said, "Go away! I need quiet." He left immediately. Boundaries: end of outer sentence only (after "immediately") Non-boundary: "!" inside quotation marks — part of quoted content

Challenge 4: Informal / Social Media Text

SMS, tweets, and chat messages frequently violate standard punctuation conventions:

"omg that was wild lol anyway did u see what happened yesterday" No sentence-terminating punctuation at all — human readers infer boundaries from discourse structure and context, not punctuation

Inter-annotator agreement on such text drops significantly below that for formal writing.

Challenge 5: Ellipsis and Suspension Points

"She paused... and then spoke." — three periods of ellipsis are not a sentence boundary. The parser must distinguish ellipsis from end-of-sentence.

Challenge 6: Code-Switching

Multilingual text may mix punctuation conventions from different languages. Spanish uses inverted question marks "¿" at the start of questions. A system trained on monolingual English text fails on Spanish-English mixed text.

B.18 Discuss the importance of Parsing in Natural Language Processing with suitable examples. 5M

Parsing — the process of recovering the hidden grammatical structure of a sentence — is the backbone of deep language understanding in NLP. While simple NLP tasks (spam filtering, keyword search) can work with surface text, any task requiring understanding of who did what to whom requires parsing.

1. Disambiguation of Meaning

Many sentences are structurally ambiguous. Parsing resolves this ambiguity by building an explicit structural representation:

"I saw the man with a telescope." Parse A: [VP saw [NP the man with a telescope]] → The man has the telescope. Parse B: [VP saw [NP the man] [PP with a telescope]] → I used a telescope to see him.

A machine translator, chatbot, or question-answering system that does not parse this sentence will give random results. Parsing selects the more probable interpretation.

2. Machine Translation

Syntactic structure is largely preserved across languages. Parsing the source sentence allows the MT system to correctly reorder constituents for the target language. Japanese is SOV; English is SVO — translating "John eats pizza" to Japanese requires knowing that "pizza" is the object (from the parse tree) so it can be moved before the verb.

3. Paraphrase Detection and Generation

The sentence "open borders imply increasing racial fragmentation in European countries" is paraphrasable as "open borders imply increasing racial fragmentation in the countries of Europe." The parse tree identifies the constituent "European countries" as replaceable, and substitution rules generate the paraphrase. This requires a parser to identify which constituent is eligible for replacement.

4. Information Extraction

Extracting structured facts from text requires knowing the subject, verb, and object of each clause — information only the parse tree provides:

Text: "Google acquired YouTube for $1.65 billion." Parse: [NP Google] [VP acquired [NP YouTube] [PP for $1.65 billion]] Extracted: (Acquirer=Google, Acquired=YouTube, Price=$1.65B)

5. Question Answering

Parsing a question identifies its type, head noun, and expected answer type. "What did Google acquire?" parses to: WH-NP="What" → object of "acquire" → answer is THING acquired by Google. Without parsing, the system cannot formulate the correct answer.

6. Prosody and Intonation (Speech NLP)

Parsing reveals the intonational structure of speech. The sentence "He wanted to go for a drive in the country" has a natural pause between "drive" and "in" — this pause is predicted by the parse tree (PP boundary) and used in text-to-speech synthesis.

7. Grammar Checking

Grammar checkers parse sentences and compare the resulting structure against grammatical constraints. Subject-verb disagreement ("she run fast") is detected by checking that the subject (3SG) matches the verb (non-3SG) — a structural check only possible after parsing.

B.19 Explain Context-Free Grammar (CFG) and its components with suitable examples. 5M

A Context-Free Grammar (CFG) is a formal generative grammar that describes the syntactic structure of a language through a set of production rules. It is "context-free" because each rule's left-hand side is a single non-terminal — its expansion is independent of surrounding symbols.

Formal Definition

A CFG is a 4-tuple G = (V, Σ, R, S) where:

ComponentSymbolDescriptionExample
Non-terminalsVGrammatical phrase categoriesS, NP, VP, PP, Det, N, V, P
TerminalsΣActual vocabulary words"the", "dog", "chased"
Production RulesRA → α where A ∈ V, α ∈ (V∪Σ)*NP → Det N
Start SymbolSTop-level sentence categoryS (sentence)

Example CFG for English

S → NP VP (sentence = noun phrase + verb phrase) NP → Det N (noun phrase = determiner + noun) NP → NP PP (noun phrase can contain a prepositional phrase) VP → V NP (verb phrase = verb + noun phrase) VP → VP PP (verb phrase can contain a prepositional phrase) PP → P NP (prepositional phrase = preposition + noun phrase) Det → "the" | "a" (determiners) N → "dog" | "cat" | "stick" | "man" V → "chased" | "saw" | "hit" P → "with" | "in" | "by"

Derivation Example

Parsing "The dog chased the cat" using this CFG:

S → NP VP (S → NP VP) → Det N VP (NP → Det N) → "the" N VP (Det → "the") → "the" "dog" VP (N → "dog") → "the" "dog" V NP (VP → V NP) → "the" "dog" "chased" NP → "the" "dog" "chased" Det N → "the" "dog" "chased" "the" N → "the" "dog" "chased" "the" "cat" ✓

Parsing "The dog chased the cat with a stick"

This sentence has TWO valid parses (syntactic ambiguity):

Parse 1: [S [NP the dog] [VP [VP chased [NP the cat]] [PP with a stick]]] → The dog used a stick to chase the cat. Parse 2: [S [NP the dog] [VP chased [NP [NP the cat] [PP with a stick]]]] → The dog chased the cat that had a stick.

Limitations of CFG

  • Ambiguity explosion — number of parses grows as Catalan numbers: O(4ⁿ/n^1.5) for n words
  • No probabilities — cannot choose between competing parses without extensions (PCFG)
  • Knowledge acquisition — exhaustively listing all grammar rules is impractical for natural language
  • No context sensitivity — cannot model long-distance dependencies easily

These limitations motivate the extension to PCFGs and treebank-trained parsers that learn grammar rules automatically from annotated data.

B.24 Compare Constituency Parsing and Dependency Parsing with suitable examples. 5M

Constituency parsing and dependency parsing are the two major paradigms for syntactic analysis in NLP. They answer the same underlying question — "what is the structure of this sentence?" — but use fundamentally different representational frameworks.

Constituency Parsing — Overview

Constituency parsing divides a sentence into nested constituents (phrases) using a phrase-structure grammar. The output is a parse tree where internal nodes are phrase labels (NP, VP, S) and leaf nodes are words.

Sentence: "John loves Mary." Constituency parse: [S [NP John] [VP [V loves] [NP Mary]]] Tree structure: S / \ NP VP | / \ John V NP loves | Mary

Dependency Parsing — Overview

Dependency parsing identifies directed head-dependent relationships between words. The output is a dependency graph with words as nodes and labeled arcs showing grammatical relations.

Sentence: "John loves Mary." Dependency parse: loves ← ROOT John ← nsubj(loves) [subject of "loves"] Mary ← obj(loves) [object of "loves"] Graph: loves → John (arc label: nsubj) loves → Mary (arc label: obj)

Projectivity — A Key Difference

A dependency tree is projective if dependency arcs don't cross when drawn above the sentence. Constituency parsing always produces projective analyses; dependency parsing can produce non-projective analyses (important for free word-order languages):

Czech example of non-projective dependency: "Knihu jsem mu dal" ("The book I gave him" — book is object of "gave" but separated) book → gave (object arc crosses over "I" and "him")

  • Use dependency when: head-modifier relations are primary (semantic role labeling, relation extraction), language has free word order, or you need a lighter, simpler representation

B.28 Explain Top-Down and Bottom-Up Parsing with suitable examples. 5M

Top-down and bottom-up are the two fundamental strategies for traversing the search space of possible parse trees. They differ in the direction of derivation and the source of information used to guide parsing.

Top-Down Parsing

Definition: Begins with the start symbol S and repeatedly expands non-terminals using grammar rules (derivation), moving downward toward the terminal words of the input. It predicts what the sentence should look like.

Algorithm (Recursive Descent):

  1. Start with S as the current goal
  2. Choose a grammar rule for S (e.g., S → NP VP)
  3. Recursively parse NP against the start of input, then VP against the remainder
  4. Backtrack if no rule matches; try the next alternative
  5. Succeed when all input is matched; fail if no alternatives remain
Grammar: S → NP VP | VP NP → Det N | PN VP → V NP | V Det → "the", N → "cat", V → "sat", PN → "John" Input: "John sat" Top-Down trace: Try: S → NP VP Try: NP → Det N Det: need "the", got "John" → FAIL Try: NP → PN PN: "John" matches ✓ NP done. Now VP: Try: VP → V NP V: "sat" matches ✓ NP: no more input → FAIL Try: VP → V V: "sat" matches ✓ VP done. Input consumed. SUCCESS ✓

Problems with top-down parsing:

  • Left recursion — S → S NP causes infinite expansion before matching any input
  • Wasted work — may expand many rules that ultimately don't match the input
  • Repeated subproblems — without memoization, same sub-tree computed many times

Bottom-Up Parsing

Definition: Begins with the input words (terminals) and applies grammar rules in reverse — reducing sequences of symbols to non-terminals — working upward toward the start symbol S.

Algorithm (Shift-Reduce):

  1. Initialize: empty stack, input buffer contains all words
  2. Shift: move next input token onto stack
  3. Reduce: if top of stack matches a rule's RHS, replace with LHS
  4. Accept if stack = [S] and buffer empty; error otherwise
Grammar: S → NP VP, NP → Det N, VP → V, Det → "the", N → "cat", V → "sat" Input: "the cat sat" Stack Buffer Action [] the cat sat Shift [the] cat sat Reduce: Det → "the" [Det] cat sat Shift [Det, cat] sat Reduce: N → "cat" [Det, N] sat Reduce: NP → Det N [NP] sat Shift [NP, sat] [] Reduce: V → "sat" [NP, V] [] Reduce: VP → V [NP, VP] [] Reduce: S → NP VP ✓

Comparison Summary

PropertyTop-DownBottom-Up
DirectionS → words (expansion)Words → S (reduction)
StrategyPrediction-drivenEvidence-driven
Left recursionFails (infinite loop)Handles naturally
Wasted workMay explore wrong rulesOnly matches actual input
Example algorithmsRecursive Descent, EarleyShift-Reduce, CYK, LR

Modern parsers often combine both strategies: Earley's algorithm is a top-down parser with bottom-up filtering (it predicts top-down but only adds items bottom-up when evidence in the input supports them), giving O(n³) worst-case complexity for any CFG.

B.30 Explain the CYK Parsing Algorithm with a suitable example. 5M

The Cocke-Younger-Kasami (CYK) algorithm is a dynamic programming, bottom-up chart parsing algorithm that efficiently finds all valid parse trees for a sentence given a CFG in Chomsky Normal Form (CNF). It is the foundation of probabilistic chart parsing (PCFG-based parsing).

Prerequisite: Chomsky Normal Form (CNF)

CYK requires that every grammar rule be in one of two forms:

A → BC (two non-terminals on the right) A → w (one terminal on the right) Example CNF Grammar: S → NP VP NP → Det N VP → V NP Det → "the" | "a" N → "dog" | "cat" V → "chased"

Any CFG can be converted to CNF by introducing new non-terminals to binarize rules with more than 2 symbols on the right.

The CYK Table

CYK builds a triangular table T where T[i][j] stores the set of non-terminals that can span words i through j (1-indexed). The sentence is accepted if S ∈ T[1][n].

Worked Example

Sentence: "the dog chased the cat" (n=5 words)

No. k=2: Det+(N+V): Det+∅ → ∅ T[2][4]: k=2: N+V+Det: ∅. k=3: (N+V)+Det: ∅ T[3][5]: k=3: V+(Det+N): V+NP → VP ✓ → {VP} Step 4 — Length-4 spans: T[2][5]: k=2: N+VP → ? (no rule). k=3: (N+V)+NP → ∅. k=4: ? k=2: N+{VP[3-5]}: nothing maps N+VP T[1][4]: k=1: Det+{N,V,Det}: none. k=3: NP+{V+Det}: ∅ Step 5 — Full span T[1][5]: k=1: Det+{N+V+Det+N[2-5]}: not found k=2: NP+VP[3-5] → NP+VP → S ✓ → T[1][5] = {S} → ACCEPT ✓

Probabilistic CYK

For PCFGs, each table entry stores not just the set of non-terminals but also their Viterbi probability — the probability of the best parse tree for that span. The final parse is obtained by backtracking through the table to find the highest-probability derivation. This is the basis of all modern PCFG-based constituency parsers.

B.31 Explain Earley's Parsing Algorithm and discuss its advantages. 5M

Earley's Algorithm (Jay Earley, 1970) is a top-down chart parsing algorithm that can handle any context-free grammar — including ambiguous, nullable, and left-recursive grammars — without requiring CNF conversion. It processes input left-to-right in O(n³) worst case, O(n²) for unambiguous grammars.

Core Data Structure: Earley Items

An Earley item (also called a dotted rule) is written as [A → α • β, i, j] and means:

  • We are trying to build an A constituent
  • We have already parsed α, starting at position i, currently at position j
  • We still need to parse β to complete this A
Example item: [NP → Det • N, 0, 1] Meaning: "We're building an NP; we've seen a Det from position 0 to 1; we still need an N starting at position 1."

Three Operations

OperationTriggerAction
PredictDot before non-terminal B in item [A → α • Bβ, i, j]Add [B → •γ, j, j] for all rules B → γ in grammar
ScanDot before terminal w in item [A → α • wβ, i, j] and input[j] = wAdd [A → αw • β, i, j+1] to chart[j+1]
CompleteItem [B → γ•, j, k] is complete (dot at end)For all [A → α • Bβ, i, j], add [A → αB • β, i, k]

Worked Example

Grammar: S → NP VP, NP → "John", VP → V NP, V → "loves", NP → "Mary" Input: "John loves Mary" (positions 0, 1, 2, 3) Chart[0]: [S → •NP VP, 0, 0] (Initial item) [NP → •"John", 0, 0] (Predict: S needs NP) Chart[1]: (after scanning "John") [NP → "John"•, 0, 1] (Scan) [S → NP•VP, 0, 1] (Complete: NP done, advance S) [VP → •V NP, 1, 1] (Predict: S needs VP) [V → •"loves", 1, 1] (Predict: VP needs V) Chart[2]: (after scanning "loves") [V → "loves"•, 1, 2] (Scan) [VP → V•NP, 1, 2] (Complete: V done) [NP → •"Mary", 2, 2] (Predict: VP needs NP) Chart[3]: (after scanning "Mary") [NP → "Mary"•, 2, 3] (Scan) [VP → V NP•, 1, 3] (Complete: NP done) [S → NP VP•, 0, 3] (Complete: VP done → ACCEPT ✓)

B.33 Explain Shift-Reduce Parsing with a suitable example. 5M

Shift-Reduce Parsing is a bottom-up parsing strategy that simulates a rightmost derivation in reverse. It uses two data structures — a stack and an input buffer — and at each step chooses between two actions: shift (push the next input token onto the stack) or reduce (collapse the top of the stack using a grammar rule).

Algorithm Steps

  1. Initialize: empty stack, input buffer = all input tokens + END marker
  2. Accept: if stack = [S] and buffer = [END] → parsing succeeded
  3. Error: if no action can be taken → parsing failed
  4. At each step, choose:
    • Shift: Move the next symbol from the buffer onto the top of the stack
    • Reduce: If the top k elements of the stack match the right-hand side of rule A → α, pop k elements and push A

Four Operations in Detail

OperationWhen AppliedEffect
ShiftNo reduction is possibleMove next input token → stack top
ReduceTop of stack matches rule RHSReplace RHS symbols with LHS non-terminal
AcceptStack = [S], buffer emptyParse successful
ErrorNo shift or reduce possibleInput is not in the language

Worked Example

Grammar: S → NP VP NP → Det N VP → V NP Det → "the" N → "dog" | "cat" V → "chased" Input: "the dog chased the cat" Stack Buffer Action ───────────────────────────────────────────────────── [] [the,dog,chased,the,cat] Shift [the] [dog,chased,the,cat] Reduce: Det → "the" [Det] [dog,chased,the,cat] Shift [Det,dog] [chased,the,cat] Reduce: N → "dog" [Det,N] [chased,the,cat] Reduce: NP → Det N [NP] [chased,the,cat] Shift [NP,chased] [the,cat] Reduce: V → "chased" [NP,V] [the,cat] Shift [NP,V,the] [cat] Reduce: Det → "the" [NP,V,Det] [cat] Shift [NP,V,Det,cat] [] Reduce: N → "cat" [NP,V,Det,N] [] Reduce: NP → Det N [NP,V,NP] [] Reduce: VP → V NP [NP,VP] [] Reduce: S → NP VP [S] [] ACCEPT ✓

The Oracle / Conflict Problem

A fundamental challenge in shift-reduce parsing is that at any point, multiple actions may be valid: shift-reduce conflicts (should I shift the next token or reduce what's on the stack?) and reduce-reduce conflicts (which of two applicable rules should I reduce with?). The parser needs an oracle to resolve these:

  • LR(k) parsers — use a finite automaton to make deterministic decisions based on k tokens of lookahead
  • Statistical oracles — train a classifier on treebank data to predict the correct action at each step
  • Neural arc-eager parsers — use BiLSTM/Transformer to score actions; used in state-of-the-art dependency parsers

Complexity

Best case (no conflicts): O(n) — linear time parsing Worst case (backtracking): O(n³) — when every decision is wrong and must backtrack Typical NLP use (statistical oracle): O(n) — nearly linear with trained oracle

Shift-reduce parsing is the basis of all modern neural dependency parsers (arc-eager, arc-standard transition systems), where each transition (shift/left-arc/right-arc) is predicted by a neural classifier.

Probabilistic Parsing — PCFG
B.36 What is the importance of Probabilistic Context-Free Grammars (PCFGs)? Discuss their advantages and disadvantages. 5M

A Probabilistic Context-Free Grammar (PCFG) extends a plain CFG by attaching a probability to every production rule. This probability encodes how often a non-terminal expands in a particular way — derived from corpus statistics. PCFGs transform parsing from a purely structural problem into a probabilistic estimation problem, enabling principled ambiguity resolution.

Formal Definition

A PCFG is a CFG G = (V, Σ, R, S) augmented with a probability function P: R → (0,1] such that for each non-terminal A, the probabilities of all rules with A on the left-hand side sum to 1:

∑_{A → α ∈ R} P(A → α) = 1 for all A ∈ V Example PCFG: S → NP VP [1.00] NP → Det N [0.60] NP → NP PP [0.40] VP → V NP [0.70] VP → VP PP [0.30] Probability of a parse tree = PRODUCT of all rule probabilities used P(tree) = 1.00 × 0.60 × 0.70 × 0.60 = 0.252 (for a specific derivation)

Importance of PCFGs

  • Disambiguation — when a sentence has multiple parses, select the highest-probability tree (Viterbi parse)
  • Data-driven — probabilities are estimated by maximum likelihood from a treebank: P(A → α) = count(A → α) / count(A)
  • Probabilistic foundation — enables Bayesian extensions, expectation-maximization for unsupervised learning, and integration with language models
  • Machine Translation — synchronous PCFGs model translation as probabilistic rule-pair derivations
  • Efficient search — Viterbi CYK finds the best parse in O(n³) without enumerating all parses

Advantages of PCFGs

AdvantageDescription
Principled ambiguity resolutionSelects the most probable parse rather than an arbitrary one
Learnable from dataParameters estimated from treebanks using MLE — no hand-crafting
Compatible with existing algorithmsCYK and Earley both extend naturally to PCFG with log-probability scores
Foundation for extensionsLexicalized PCFGs, head-driven models, and neural CFGs are all extensions of the PCFG framework
Inside-outside algorithmEnables unsupervised PCFG training via expectation-maximization

Disadvantages / Limitations

Context independenceRule probabilities don't depend on surrounding context — NP expands the same way whether it's a subject or objectLexicalized PCFGs (head-word conditioning)

Despite these limitations, PCFGs remain the standard probabilistic framework for constituency parsing. Modern parsers extend PCFGs with lexicalization (conditioning rule probabilities on head words) and neural models that can capture contextual and long-range dependencies that plain PCFGs miss.

B.37 Explain the structure and working of a Probabilistic Context-Free Grammar with a suitable example. 5M

A PCFG operates by assigning a probability score to every possible derivation of a sentence, then selecting the derivation with the highest probability as the preferred parse. This turns parsing into a maximum a posteriori (MAP) estimation problem.

Structure of a PCFG

A PCFG consists of the same four components as a CFG, plus a probability assignment:

PCFG = (V, Σ, R, S, P) where P: R → (0,1] Sample PCFG: S → NP VP [P = 1.00] NP → Det N [P = 0.60] ← 60% of NPs are Det+N NP → NP PP [P = 0.25] ← 25% of NPs include PP NP → PN [P = 0.15] ← 15% of NPs are proper nouns VP → V NP [P = 0.55] ← 55% of VPs are transitive VP → V [P = 0.25] ← 25% of VPs are intransitive VP → VP PP [P = 0.20] ← 20% of VPs have PP adjunct PP → P NP [P = 1.00] Terminals: Det → "the"[0.7] | "a"[0.3] N → "man"[0.3] | "telescope"[0.3] | "cat"[0.4] V → "saw"[0.6] | "chased"[0.4] P → "with"[0.5] | "in"[0.5]

How PCFG Selects Between Parses

For the ambiguous sentence "I saw the man with a telescope", there are two parses. The PCFG assigns each a probability:

Parse A: VP → VP PP (I used a telescope to see) P(Parse A) = P(S→NP VP) × P(VP→VP PP) × P(VP→V NP) × ... = 1.00 × 0.20 × 0.55 × ... = 0.18 Parse B: NP → NP PP (the man has a telescope) P(Parse B) = P(S→NP VP) × P(VP→V NP) × P(NP→NP PP) × ... = 1.00 × 0.55 × 0.25 × ... = 0.22 PCFG selects Parse B (P = 0.22 > 0.18)

Parameter Estimation from a Treebank

PCFG probabilities are estimated from an annotated treebank using Maximum Likelihood Estimation (MLE):

P(A → α) = count(A → α used in treebank) / count(A expanded in treebank) Example from Penn Treebank: NP → Det N appears 12,000 times NP expands 20,000 times total → P(NP → Det N) = 12,000 / 20,000 = 0.60

Viterbi Parsing

Finding the best parse is done using the Viterbi algorithm — a dynamic programming algorithm that fills in the CYK table with the maximum probability derivation for each span, rather than all possible derivations:

viterbi[A][i][j] = max over all rules A → BC and split points k of: P(A → BC) × viterbi[B][i][k] × viterbi[C][k][j] Final answer: viterbi[S][0][n] = probability of best parse for full sentence

The backpointer table is stored alongside the viterbi table so the actual best parse tree can be reconstructed by tracing back through the maximum decisions. This is exactly what modern PCFG-based constituency parsers do.

B.38 Discuss how PCFGs can be used to resolve syntactic ambiguity. 5M

Syntactic ambiguity — sentences with multiple valid parse trees — is one of the most fundamental challenges in NLP. Plain CFGs have no mechanism to prefer one reading over another. PCFGs solve this by turning parse selection into a probabilistic inference problem: the correct parse is the one with the highest probability according to corpus-trained rule probabilities.

PCFG Resolution Mechanism

The PCFG scores every possible parse tree with the product of probabilities of all rules used in that derivation. The Viterbi parse — the tree with the maximum probability — is returned as the system's best parse.

Sentence: "The boy ate the food with a spoon." P(Parse B) ∝ 0.70 × 0.40 = 0.280 PCFG selects Parse B (0.280 > 0.210) → "the food had a spoon" reading

Limitations of Basic PCFG for Ambiguity Resolution

Plain PCFGs use context-free rule probabilities — they don't condition on the specific words involved. This means the PP attachment decision "with a spoon" is made using the same probabilities as "with a telescope", even though lexical semantics strongly suggests different attachments. A telescope is used for seeing (VP attachment) but a spoon is used for eating, which is itself the VP — both actually attach to VP.

Lexicalized PCFGs

To address this limitation, lexicalized PCFGs (Collins 1999, Charniak 2000) condition rule probabilities on the head word of each phrase:

P(VP → VP PP | head-V = "eat") vs P(VP → VP PP | head-V = "see") P(NP → NP PP | head-N = "man") vs P(NP → NP PP | head-N = "food") These lexicalized probabilities much better capture world knowledge encoded in the training corpus.

Modern neural parsers (based on BiLSTMs and Transformers) can effectively learn context-sensitive attachment preferences without explicit lexicalization, by encoding rich word and sentence representations that capture semantic similarity, animacy, and typical instrument-action associations.

Generative & Discriminative Parsing Models
B.41 What are Discriminative Models for Parsing? Explain their characteristics and applications. 5M

Discriminative models for parsing directly model the conditional probability P(parse tree | sentence) — the probability of a specific structural analysis given the observed input — without making any assumptions about how the sentence was generated. They are trained to discriminate correct parses from incorrect ones.

Core Principle

Generative: models P(x, y) → uses Bayes' rule to get P(y|x) Discriminative: models P(y|x) → directly, without modeling P(x) Where: x = sentence (observation) y = parse tree (label)

Key Characteristics

  1. Direct conditional modeling — P(y|x) is the quantity of interest; no generative process needed
  2. Rich, overlapping features — can use any feature of x and y jointly, even correlated ones:
    • Word n-grams around a constituent boundary
    • POS tag sequences
    • Distance between head and dependent
    • Punctuation context
    • Word embeddings and neural representations
  3. No independence assumptions — generative models require conditional independence between rules; discriminative models can capture arbitrary interactions
  4. Iterative training — trained by maximizing the conditional likelihood of correct parses, or minimizing a margin (SVM-style), using gradient descent over many passes
  5. Require a decoding algorithm — to find the best parse at test time, a search algorithm (Viterbi, beam search, CYK) must be applied to the learned scoring function

Applications

  • Constituency parsing — discriminative rerankers rerank the n-best parses from a PCFG using richer features
  • Dependency parsing — neural transition-based and graph-based dependency parsers are all discriminative
  • Sentence boundary detection — CRFs and MaxEnt classifiers for punctuation classification

B.43 Differentiate between Generative and Discriminative Models for Parsing. 5M

Generative and discriminative models represent two fundamentally different philosophies for building probabilistic parsers. Both aim to find the best parse tree for a sentence, but they model different probability distributions and make different assumptions about the data.

Core Philosophical Difference

Generative model: → Asks: "How likely is it that the grammar generated both this sentence AND this parse tree?" → Models: P(sentence, parse) = P(x, y) → Uses Bayes' rule: P(parse|sentence) = P(sentence,parse) / P(sentence) Discriminative model: → Asks: "Given this sentence, which parse tree best explains it?" → Models: P(parse|sentence) = P(y|x) directly → Does NOT model how the sentence was generated

Analogy

Consider a doctor diagnosing a disease from symptoms:

  • Generative approach — model how each disease causes symptoms (P(symptoms | disease)), then use Bayes' rule to infer the most likely disease. You need a complete causal model of every disease.
  • Discriminative approach — directly learn which symptom patterns predict which disease (P(disease | symptoms)) from labeled patient records. No causal model needed; just learn the mapping from observations to diagnosis.

Hybrid Approaches

Many state-of-the-art parsers combine both paradigms:

  • Reranking — use a generative PCFG to produce n-best parses, then a discriminative reranker to select the best using rich features
  • HELM/fHELM — feed discriminative classifier posteriors into a generative HMM for sentence boundary detection
  • Neural PCFG — use neural networks to predict rule probabilities conditioned on sentence context — combining the probabilistic structure of PCFGs with the feature richness of discriminative models

B.58 Explain how a probabilistic parser can choose between two competing parse trees for an ambiguous sentence. 5M

A probabilistic parser resolves ambiguity by assigning a score (probability or log-probability) to every candidate parse tree and selecting the one with the highest score — the Viterbi parse. The scoring function is derived from training data, encoding which structural choices are statistically preferred in real language.

The Ambiguity Problem

Ambiguous sentence: "The student solved the difficult problem." Possible structural ambiguities: 1. PP attachment (if there were a PP) 2. Adjective attachment — "difficult" clearly modifies "problem" here, but consider: "She saw the man with glasses." Let's use the classic: "I saw the man with a telescope." → Parse A: [VP saw [NP the man]] [PP with telescope] (I used telescope) → Parse B: [VP saw [NP [the man] [PP with telescope]]] (man had telescope)

Step 1: Assign PCFG Probabilities

Grammar rules with corpus-estimated probabilities: VP → VP PP [P = 0.35] ← VP takes PP adjunct 35% of time NP → NP PP [P = 0.28] ← NP takes PP modifier 28% of time VP → V NP [P = 0.65] NP → Det N [P = 0.72]

Step 2: Compute Parse Tree Probabilities

Parse A: S → NP VP, VP → VP PP, VP → V NP, NP → Det N (×2), PP → P NP P(Parse A) = P(S→NP VP) × P(NP→PN) × P(VP→VP PP) × P(VP→V NP) × P(NP→Det N) × P(PP→P NP) × P(NP→Det N) = 1.00 × 1.00 × 0.35 × 0.65 × 0.72 × 1.00 × 0.72 = 0.118 Parse B: S → NP VP, VP → V NP, NP → NP PP, NP → Det N (×2), PP → P NP P(Parse B) = P(S→NP VP) × P(NP→PN) × P(VP→V NP) × P(NP→NP PP) × P(NP→Det N) × P(PP→P NP) × P(NP→Det N) = 1.00 × 1.00 × 0.65 × 0.28 × 0.72 × 1.00 × 0.72 = 0.094

Step 3: Select the Viterbi Parse

P(Parse A) = 0.118 ← SELECTED (higher probability) P(Parse B) = 0.094 Parser output: Parse A Interpretation: "I used a telescope to see the man."

Implementation: Viterbi CYK

In practice, a probabilistic parser uses the Viterbi CYK algorithm — a dynamic programming algorithm that fills a parse table with the maximum-probability derivation for each span [i, j], rather than enumerating all parses:

viterbi[A][i][j] = max_{k, A→BC} P(A→BC) × viterbi[B][i][k] × viterbi[C][k][j] This computes the best score for each span incrementally, avoiding the exponential blowup of explicit parse enumeration. Time complexity: O(n³ × |grammar rules|)

Limitations and Extensions

  • Plain PCFG — rule probabilities are context-free; ignore the specific words involved ("telescope" vs "glasses")
  • Lexicalized PCFG — condition probabilities on head words: P(VP→VP PP | head-V = "saw") captures that "saw with telescope" is a common instrumental construction
  • Neural parsers — use word embeddings and sentence encoders (BiLSTM, BERT) to compute context-sensitive scores for each rule application, effectively capturing world knowledge that bare PCFGs miss

The core insight is that probabilistic parsing transforms the linguistic question "which parse is correct?" into the statistical question "which parse is most probable given the training data?" — making it a tractable, data-driven inference problem.
