✉1 Basic Definitions: What is Data, Information, Knowledge and Data Mining? 5M

Data is raw, unprocessed facts and figures (numbers, text, images, sensor readings) with no context attached. Information is data that has been organized/processed to carry meaning (e.g., a sales total). Knowledge is the actionable insight or pattern derived from information (e.g., “sales spike every December”).

Data Mining is the process of discovering meaningful, previously-unknown patterns, correlations and trends from large volumes of data, using methods drawn from statistics, machine learning and database systems.

Why “KDD”?

To refer to extracting gold from rock, we say “gold mining”, not “rock mining”. By the same logic, data mining should really have been called “knowledge mining from data” — shortened, this became Knowledge Discovery from Data (KDD). Many treat the two terms as synonyms; more precisely, data mining is the core pattern-extraction step inside the larger, 7-step KDD process (cleaning → integration → selection → transformation → mining → evaluation → presentation).

✉2 What is Data Mining? What Kinds of Data can be Mined? 5M

Data mining is the process of discovering hidden, meaningful patterns and knowledge from large data repositories using statistical, machine-learning and database techniques. It turns a large, information-poor collection of raw data into compact, actionable knowledge — e.g., Google Flu Trends aggregating search queries to predict flu activity up to two weeks faster than traditional systems.

Worked example: Web Mining

A search engine cleans raw web logs (step 1), integrates logs from multiple servers (step 2), selects only the clickstream data relevant to a marketing question (step 3), aggregates page visits per session (step 4), mines frequent navigation-path patterns (step 5), filters out trivial paths like the homepage-only visit (step 6), and finally visualizes the top navigation paths for the web team (step 7). Because the process is iterative, a noisy pattern found in step 6 can send the analyst back to step 1 to clean the data further.

✉5 Data Preprocessing: Major Tasks 5M

Real-world data is dirty — incomplete, noisy and inconsistent — and poor-quality data produces poor-quality mining results (“garbage in, garbage out”). Data preprocessing corresponds to the first four steps of KDD and is often the most time-consuming part of a real project.

Preprocessing Pipeline

Symmetric vs asymmetric binary: in a symmetric binary attribute (e.g., Gender) both outcomes matter equally; in an asymmetric one (e.g., a disease test) the “presence” outcome (usually coded 1) is more significant, so similarity measures like Jaccard deliberately ignore 0-0 (both-absent) matches.

✉8 Market Basket Analysis: The Apriori Algorithm and FP-Growth 5M

Market Basket Analysis finds items frequently bought together (e.g., Diaper→Beer) to guide store layout, catalog design and cross-marketing. It relies on:

Support(X->Y) = (transactions with X and Y) / (total transactions) Confidence(X->Y) = (transactions with X and Y) / (transactions with X)

An itemset is frequent if its support ≥ minsup; a rule is strong if it meets both minsup and minconf.

Apriori

Uses the Apriori (downward-closure) property: every subset of a frequent itemset must itself be frequent, so any candidate with an infrequent subset is pruned before even scanning the DB. It works level-wise: find L1, self-join & prune to get C2, scan DB to get L2, and so on until Lk is empty — requiring k scans for max pattern length k.

FP-Growth

Avoids candidate generation entirely. It compresses the database into a compact FP-tree (built from an F-list of items sorted by descending frequency) in just two scans, then mines it recursively via conditional pattern bases and conditional FP-trees, growing long patterns directly from short ones.

AspectAprioriFP-Growth
SearchBreadth-first, level-wiseDepth-first, divide-and-conquer
CandidatesExplicitly generated & testedNone — grown from conditional trees
DB scansOne per level (k scans)Exactly two, total
SpeedSlower on dense/long-pattern dataTypically an order of magnitude faster

Both rely on the same anti-monotone Apriori property, but exploit it differently — Apriori prunes before counting; FP-Growth only ever grows from combinations already known to be locally frequent.

✉9 From Association Analysis to Correlation Analysis 5M

Support and confidence alone can be misleading: a rule can look “strong” purely because its consequent is popular overall, not because the items are truly related.

Classic example (AllElectronics, 10,000 transactions)

6,000 buy games, 7,500 buy videos, 4,000 buy both Confidence(game->video) = 4000/6000 = 66.7% (looks strong) But baseline P(video) = 7500/10000 = 75% > 66.7% => game and video are actually NEGATIVELY correlated

Correlation Measures

MeasureFormulaInterpretation
LiftP(A∪B) / (P(A)×P(B))>1 positive, =1 independent, <1 negative correlation
Chi-Square (χ²)Compares observed vs expected contingency-table countsLarge χ² ⇒ correlated; sign of the gap shows direction
All-Confidencesup(A∪B) / max(sup(A),sup(B))Null-invariant (unaffected by transactions with neither item)
Kulczynski½[P(A|B)+P(B|A)]Null-invariant; often paired with the Imbalance Ratio

Lift for the example above = 0.4/(0.6×0.75) = 0.89 < 1, confirming the negative correlation the raw confidence hid. Because lift and χ² are distorted by “null transactions” (those containing neither item, which dominate large sparse datasets), null-invariant measures such as all-confidence, cosine and Kulczynski are generally preferred for correlation analysis on real-world retail data.

Items naturally form concept hierarchies (Skim Milk → 2% Milk → Milk), and multilevel mining finds rules across these levels.

A single-dimensional rule repeats one predicate (buys(X,milk)⇒buys(X,bread)). A multidimensional rule spans ≥2 predicates:

TypeDefinitionExample
Inter-dimensionNo repeated predicateage(X,"19-25") ∧ occupation(X,"student") ⇒ buys(X,"coke")

✉11 Naive Bayes Classification 5M

Bayes' Theorem gives the posterior probability of a class C given evidence X:

P(C|X) = P(X|C) * P(C) / P(X) [posterior = likelihood x prior / evidence]

The Naïve Bayes classifier adds a simplifying (“naïve”) assumption: all attributes are conditionally independent given the class, so:

P(X|Ci) = P(x1|Ci) * P(x2|Ci) * ... * P(xn|Ci) Predict Ci that maximizes P(X|Ci) * P(Ci)

Mini worked example

For X = (age≤30, income=medium, student=yes, credit=fair) on the standard buys_computer dataset: P(yes)=0.643, P(no)=0.357. Multiplying the four class-conditional probabilities gives P(X|yes)=0.044 and P(X|no)=0.019; multiplying by the priors gives 0.028 vs 0.007 — so the classifier predicts buys_computer = yes.

FeatureDetail
Zero-probability problemOne zero conditional probability wipes out the entire product
Fix: Laplacian correctionAdd 1 to every count, add (#categories) to the denominator
AdvantagesFast, simple, needs only one pass, works well on high-dimensional text data
DisadvantagesConditional-independence assumption rarely holds exactly in practice

When attribute dependencies matter too much to ignore, Bayesian Belief Networks generalize Naïve Bayes by explicitly modelling a graph of dependencies, trading its speed/simplicity for accuracy.

✉12 Supervised vs Unsupervised Learning 5M

Supervised learning trains on labelled data (input + known output) to learn a mapping X→Y usable on new inputs; performance is measured directly against true labels. Unsupervised learning works on unlabelled data, discovering hidden structure without any “correct answer” to learn from.

AspectSupervisedUnsupervised
DataLabelled (X, Y)Unlabelled (X only)
GoalPredict Y for new XDiscover structure/groupings in X
FeedbackDirect error vs true labelNo ground truth; internal criteria only
TasksClassification, RegressionClustering, Association Rule Mining, Outlier detection
Algorithms (this syllabus)Naïve Bayes (Unit 3)Apriori/FP-Growth (Unit 2), k-Means/DBSCAN (Unit 4)
EvaluationAccuracy, Precision, Recall, F1, RMSESilhouette score, intra/inter-cluster distance

A third category, semi-supervised learning, mixes a small labelled set with abundant unlabelled data (useful when labelling is expensive, e.g., medical images). Reinforcement learning is a separate paradigm again, where an agent learns from rewards/penalties through interacting with an environment rather than from a fixed dataset. Recognizing which category an algorithm from this syllabus belongs to (e.g., Naïve Bayes = supervised classification; Apriori = unsupervised pattern discovery) is a common short-answer exam question.

✱A.9 Define Nominal Attribute with examples. 2M

✱A.11 Define Ordinal Attribute with examples. 2M

A.26 Briefly explain Pixel-oriented and Icon-based visualization techniques. 2M
Pixel-oriented: for m dimensions, m separate windows are created; each record's m values are mapped to m pixels (one per window) whose colour encodes the value — useful for very large, high-dimensional datasets. Pixels can also be laid out in circle segments to save space.

Icon-based (e.g., Chernoff Faces): maps data dimensions onto features of an icon — e.g., eyebrow slant, eye size, nose length — so a human can visually compare many records at once by comparing "faces". Stick-figures similarly map two attributes to axes and the rest to limb angle/length.

A.28 How is proximity measured for Nominal attributes? 2M
Method 1 — Simple Matching: d(i, j) = (p − m) / p, where p is the total number of nominal attributes and m is the number that match between objects i and j.

Method 2 — Binary encoding: create a new asymmetric binary attribute for each of the M possible nominal states, then apply binary-attribute dissimilarity measures.

Nominal proximity only checks equality/inequality since the values carry no order.
✱A.29 Define the Jaccard Coefficient for asymmetric binary attributes. 2M
For two objects with asymmetric binary attributes, define a contingency table of counts q (1-1 matches), r (1-0), s (0-1), t (0-0).
Jaccard similarity: J(i,j) = q / (q + r + s) Asymmetric distance: d(i,j) = (r + s) / (q + r + s)
The Jaccard coefficient deliberately ignores the t (0-0, both-absent) count because, for asymmetric attributes such as disease presence, agreeing on absence is not informative. Jaccard is equivalent to what the slides call "coherence".

z = (X - mu) / sigma
It expresses the distance of a raw score from the mean in units of standard deviation — negative when below the mean, positive when above. A more robust alternative uses the mean absolute deviation instead of σ, which is less sensitive to outliers.

Unit 2 — Association Analysis: Basic Concepts
✱A.42 What is Market Basket Analysis? Give a real-world example. 2M
Market Basket Analysis analyzes customer buying habits by finding items frequently placed together in a "shopping basket", revealing associations between products.

Example: if customers buying milk also frequently buy bread, a retailer can place bread near milk (to boost combined sales) or at opposite ends of the store (to make customers walk past other items). It also guides catalog design, cross-marketing, and sale-campaign planning — e.g., discounting printers to boost computer sales when the two are bought together.
✱A.43 Define Support and Confidence of an association rule X → Y. 2M
Support(X->Y) = P(X and Y) = (transactions containing X and Y) / (total transactions) Confidence(X->Y) = P(Y|X) = (transactions containing X and Y) / (transactions containing X)
Example: If Beer→Diaper has support 60% and confidence 100% over 5 transactions, it means 60% of all transactions contain both, and every transaction with beer also contains diapers. A rule is strong only if it meets both a minimum support and a minimum confidence threshold.
✱A.44 What is a Frequent Itemset? When is an itemset called "frequent"? 2M
An itemset is a set of one or more items (a k-itemset has k items). Its absolute support (support count) is how many transactions contain it; its relative support is the fraction of transactions containing it.

An itemset X is called frequent if its support is no less than a chosen minsup threshold. Frequent itemsets are the building blocks from which strong association rules are later generated.
✱A.45 State the Apriori Property (downward-closure property). 2M

If an itemset is infrequent, all of its supersets must also be infrequent — equivalently, every subset of a frequent itemset must itself be frequent.

This anti-monotone property lets Apriori prune the search space aggressively: once a candidate itemset is found to have a non-frequent subset, it is discarded immediately without even scanning the database, dramatically reducing the number of candidates that must be tested.

Unit 2 — From Association Analysis to Correlation Analysis
✱A.49 Why is Correlation Analysis needed in addition to Support and Confidence? Give the classic games-videos example. 2M
Support and confidence alone can generate misleading rules: a rule can have high confidence purely because the consequent itself is very popular, not because the two items are truly related.

Classic example (AllElectronics, 10,000 transactions): 6,000 buy computer games, 7,500 buy videos, 4,000 buy both.
Rule: game -> video Support = 4000/10000 = 40% Confidence = 4000/6000 = 66.7% (looks strong!) But P(video) = 7500/10000 = 75% > 66.7% => buying a game actually LOWERS the chance of buying video => game and video are NEGATIVELY correlated, despite the 'strong' rule
Hence correlation measures (lift, all-confidence, cosine, Kulczynski) are used alongside support-confidence to filter out such spurious rules.
✱A.50 Define the Lift and Chi-Square (χ²) correlation measures for association rules. 2M
Lift(A,B) = P(A U B) / (P(A) * P(B))
LiftMeaning
> 1A and B positively correlated (occur together more than chance)
= 1A and B independent
< 1A and B negatively correlated
For the games-videos example: Lift = 0.4/(0.6×0.75) = 0.89 < 1, confirming negative correlation despite 66.7% confidence.

The χ² test compares observed vs expected counts in a contingency table of A, B, ¬A, ¬B; a large χ² value (checked against a critical value) indicates A and B are correlated, and the sign of (observed − expected) for the (A,B) cell shows whether the correlation is positive or negative.
✱A.51 Define All-Confidence and the Kulczynski measure. What is null-invariance? 2M
all_conf(A,B) = sup(A U B) / max(sup(A), sup(B)) Kulc(A,B) = 1/2 * [ P(A|B) + P(B|A) ]
A correlation measure is null-invariant if its value does not change when the number of transactions containing neither A nor B (the "null" transactions) changes — important because null transactions usually dominate large sparse datasets and can distort measures like lift and χ².

All-confidence, Kulczynski and cosine are null-invariant, so they are preferred over lift/χ² for large transactional databases. Kulczynski is often used together with the Imbalance Ratio (IR) IR(A,B) = |sup(A)−sup(B)| / (sup(A)+sup(B)−sup(AB)) to judge whether A and B occur with similar frequency.
Unit 3 — Supervised vs Unsupervised Learning
✱A.52 Define Supervised Learning with examples. 2M
Supervised learning trains a model on labelled data — each training example has a known input (features) and a known correct output (class label or numeric target) — so the algorithm learns a mapping X → Y that it can apply to new, unseen inputs.

Examples: Naïve Bayes, Decision Trees, k-NN and SVM for classification (spam/not-spam, disease/no-disease); Linear/Logistic Regression for regression (predicting price, temperature).

Because the "correct answers" are known during training, model performance can be directly measured using accuracy, precision, recall, etc., against the true labels.
✱A.53 Define Unsupervised Learning with examples. 2M
Unsupervised learning works on unlabelled data — there is no predefined class label or target output — and the algorithm must discover hidden structure, groupings, or patterns in the data on its own.

Examples: k-Means and Hierarchical Clustering (grouping customers into segments), Association Rule Mining/Apriori (finding co-occurring items), PCA and Outlier Analysis.

Since there is no ground truth, performance is judged with internal criteria such as intra-cluster similarity and inter-cluster dissimilarity, rather than accuracy against known labels.

✱B.2 Explain the Data Mining Functionalities in detail, with an example for each. 10M

Data mining functionalities specify the kinds of patterns to be discovered, and are broadly split into descriptive (summarize existing data) and predictive (infer unknown/future values) functions.

1. Characterization / Generalization

Summarizes and contrasts general characteristics of a target class of data, e.g., generalizing and comparing features of a "dry region" vs a "wet region" using data-cube/OLAP techniques.

2. Association & Correlation Analysis

Discovers frequent itemsets and rules of the form X → Y with support and confidence, e.g., Diaper → Beer [support 0.5%, confidence 75%]. Correlation analysis checks whether strongly-associated items are also statistically correlated (to avoid misleading rules).

3. Classification & Label Prediction

Builds a model from labelled training examples to predict class labels for new data, e.g., classifying e-mails as spam/not-spam or cars by gas mileage. Typical methods: decision trees, Naïve Bayes, SVM, neural networks.

4. Cluster Analysis

Unsupervised grouping of data into clusters that maximize intra-cluster similarity and minimize inter-cluster similarity, without predefined labels — e.g., clustering houses to find distribution/pricing patterns.

5. Outlier Analysis

Identifies data objects that don't comply with the general behaviour of the data; useful for fraud detection and rare-event analysis. One person's "noise" can be another's "treasure" (the actual object of interest).

6. Regression & Time-Series/Sequential Analysis

Predicts continuous numeric values (e.g., weather, stock price) and discovers ordered patterns over time (e.g., a customer buys a phone, then a cover, then a charger).

Together these functionalities let data mining answer both "what happened / what exists" (descriptive) and "what will happen / what class does this belong to" (predictive) questions about a dataset.

Attribute Types & Statistical Description
✱B.4 Explain the different types of attributes with examples, allowed operations, and a comparison table. 10M

An attribute is a data field representing a feature of a data object; database columns correspond to attributes and rows correspond to data objects (tuples). Attributes are classified into four main types.

1. Nominal Attributes

Categorical labels with no order (e.g., Colour: red/blue/green; Blood group: A/B/AB/O). Allowed operations: = and ≠ only, plus counting category frequency.

2. Binary Attributes

A special nominal case with exactly two states. Symmetric binary attributes have equally important outcomes (Gender). Asymmetric binary attributes have one more significant outcome, usually coded 1 for presence (Disease test result), and similarity measures like Jaccard ignore double-absence (0-0) matches.

3. Ordinal Attributes

Values with meaningful rank but unequal/undefined gaps (Education level: primary < secondary < graduate). Allowed operations: comparisons, median, mode; can be mapped to numeric ranks for further processing, but the mean is not strictly meaningful.

4. Numeric Attributes

Quantitative, measurable values supporting full arithmetic. Interval-scaled data (temperature in °C) has no true zero; ratio-scaled data (height, weight, income) has a true zero, so ratio statements ("twice as much") are valid.

Discrete vs Continuous cross-cutting distinction

Independently of the above, any attribute can be discrete (finite/countable values, e.g., number of children) or continuous (uncountably infinite values within a range, e.g., height = 165.2cm). Data Visualization
B.7 Explain the categorization of Data Visualization techniques with examples of each. 10M

Data visualization maps information onto graphical primitives to help analysts explore large datasets qualitatively, spot patterns/irregularities, and choose parameters for further quantitative work. Techniques are grouped into five categories.

1. Pixel-Oriented Techniques

For m dimensions, create m windows; each record's m values map to m coloured pixels at corresponding screen positions. To save space, pixels can be laid out in concentric circle segments instead of rectangular windows.

2. Geometric Projection Techniques

Visualize transformations/projections of data: scatterplot matrices (a grid of pairwise x-y plots), landscapes (data rendered as a 3D terrain), parallel coordinates (n parallel axes, one per attribute, with each record drawn as a connecting polyline), and projection-pursuit techniques that search for "interesting" low-dimensional projections.

3. Icon-Based Techniques

Encode data values as visual features of an icon. Chernoff faces map attributes to facial features (eye size, eyebrow slant, nose length, mouth shape); stick figures map two attributes to axes and the rest to limb angle/length, letting analysts spot patterns through overall "texture".

4. Hierarchical Techniques

Partition the screen recursively to reflect a data hierarchy: dimensional stacking nests 2D subspaces inside each other; tree-maps recursively subdivide screen area by attribute value; cone trees and InfoCube use 3D nested/concentric shapes for hierarchical information.

5. Visualizing Complex Data and Relations

For non-numeric data such as text and social networks: tag clouds represent term importance via font size/colour; network-graph visualizations show relationships such as who-follows-whom or infection-spread patterns.

Choosing the right technique depends on dimensionality and data type: pixel-oriented and parallel coordinates scale to many dimensions; Chernoff faces work best for a handful of key attributes; tree-maps and cone trees suit naturally hierarchical data.

Measuring Similarity and Dissimilarity
✱B.9 Explain the Minkowski distance family and compute Manhattan, Euclidean and Supremum distance for a given pair of points. 10M

The Minkowski distance is a generalized metric for p-dimensional numeric data objects i=(xᾑ₁,...,xᾑ₁₂) and j=(xᾑ₂₁,...,xᾑ₂₂):

d(i,j) = ( sum_k |x_ik - x_jk|^h ) ^ (1/h)

It reduces to three named metrics depending on h, and is a true metric because it satisfies positive definiteness (d(i,j)>0 for i≠j, d(i,i)=0), symmetry (d(i,j)=d(j,i)), and the triangle inequality (d(i,j) ≤ d(i,k)+d(k,j)).

Worked example

Let two data points be x1 = (1, 2) and x2 = (3, 5) (as used in the slide-style dissimilarity-matrix examples).

Interpretation

Manhattan distance sums absolute per-attribute differences (like navigating city blocks); its special case, the Hamming distance, counts differing bits between two binary vectors. Euclidean distance is the familiar straight-line distance and is most common for continuous numeric data. Supremum distance considers only the single attribute with the largest difference, useful when one dominant dimension should determine dissimilarity.

Before applying any of these, attributes should usually be standardized (z-score) so that a high-magnitude attribute (e.g., income in thousands) does not unfairly dominate a low-magnitude one (e.g., age in years).

✱B.10 Explain Cosine Similarity and compute it for the given term-frequency vectors d1 and d2. 10M

For high-dimensional, sparse vector data — most typically term-frequency vectors representing documents — cosine similarity measures the cosine of the angle between two vectors, capturing orientation (topic) rather than magnitude (length):

cos(d1, d2) = (d1 . d2) / ( ||d1|| * ||d2|| )

Worked example (from slides)

d1 = (5, 0, 3, 0, 2, 0, 0, 2, 0, 0), d2 = (3, 0, 2, 0, 1, 1, 0, 1, 0, 1)

Dot product: d1.d2 = 5*3+0*0+3*2+0*0+2*1+0*1+0*0+2*1+0*0+0*1 = 15 + 6 + 2 + 2 = 25 Magnitude of d1: ||d1|| = sqrt(5^2+3^2+2^2+2^2) = sqrt(25+9+4+4) = sqrt(42) = 6.481 Magnitude of d2: ||d2|| = sqrt(3^2+2^2+1^2+1^2+1^2+1^2) = sqrt(9+4+1+1+1+1) = sqrt(17) = 4.123 cos(d1,d2) = 25 / (6.481 * 4.123) = 25 / 26.72 = 0.94

Interpretation

A cosine similarity of 0.94 (close to the maximum of 1) indicates that documents d1 and d2 are highly similar in content/topic direction, even though their raw term counts (magnitudes) differ. This property — insensitivity to document length — is exactly why cosine similarity, not Euclidean distance, is the standard measure for information retrieval, text mining, and gene-expression comparisons.

d(i,j) = (0+1)/(2+0+1) = 1/3 = 0.33 J(i,j) = 2/(2+0+1) = 2/3 = 0.67 (similarity)

Because Gender is symmetric, it is scored using the full contingency table (both 1-1 and 0-0 agreements count); because the disease attributes are asymmetric, only positive (1-1, 1-0, 0-1) agreements matter, since two patients both not having a rare disease is uninformative. Mixing this up is a common exam pitfall.

B.12 Explain how dissimilarity is computed for a database with Attributes of Mixed Type. 5M

Real datasets usually contain a mix of nominal, binary, ordinal and numeric attributes together. A single, weighted formula combines all attribute types into one overall dissimilarity:

d(i,j) = ( sum_f delta_ij^(f) * d_ij^(f) ) / ( sum_f delta_ij^(f) )

where the per-attribute contribution dᾝῆ(f) is computed differently depending on the type of attribute f:

Attribute type fContribution d_ij(f)
Binary or Nominal0 if x_if = x_jf (match), else 1
NumericNormalized absolute distance |x_if - x_jf| / range of f
OrdinalCompute rank r_if, normalize z_if = (r_if - 1)/(M_f - 1), then treat as interval-scaled

The indicator δᾝῆ(f) is 0 if either value is missing (or if the attribute is asymmetric binary and both are 0), and 1 otherwise, so missing data is automatically excluded from the average rather than distorting it.

This mixed-type formula is what allows a single k-NN or clustering distance computation to sensibly combine, say, a patient's Blood Group (nominal), Smoker Y/N (asymmetric binary), Pain Level (ordinal) and Age (numeric) into one comparable dissimilarity score.

Data Preprocessing
✱B.13 Explain the Major Tasks in Data Preprocessing in detail, with a pipeline diagram. 10M

Data preprocessing corresponds to the first four steps of the KDD process and is often the most time-consuming stage of a real data mining project, since raw data is rarely analysis-ready.

Data Preprocessing Pipeline

1. Data Cleaning

Fills in missing values, smooths noisy data, identifies/removes outliers, and resolves inconsistencies (e.g., Age="42" but Birthday implies a different age; rating scale changed from "1,2,3" to "A,B,C" mid-dataset).

2. Data Integration

Merges multiple databases, cubes, or files, solving the entity-identification problem (matching "cust_id" to "customer_number"), removing redundancy via correlation analysis, and resolving duplicate tuples and value conflicts (e.g., differing units).

3. Data Reduction

Obtains a reduced-volume representation via dimensionality reduction (PCA, attribute subset selection, wavelet transform), numerosity reduction (histograms, clustering, sampling, regression models), or data/cube compression — while preserving analytical integrity.

4. Data Transformation and Discretization

Normalizes numeric ranges (min-max, z-score, decimal scaling), discretizes continuous attributes into intervals (binning, histogram or entropy-based), and builds concept hierarchies for nominal data.

These four tasks are not strictly sequential in practice — cleaning and integration often iterate together, and reduction/transformation choices depend on which mining algorithm will be applied downstream.

✱B.16 Explain Data Transformation by Normalization with worked numeric examples for Min-Max, Z-score, and Decimal Scaling. 10M

Normalization scales attribute values into a smaller, specified range so that no single attribute dominates a distance-based mining algorithm purely because of its raw magnitude.

1. Min-Max Normalization

v' = (v - min_A) / (max_A - min_A) * (new_max_A - new_min_A) + new_min_A

Example: income range is $12,000 to $98,000, normalized to [0.0, 1.0]. For v = $73,000:

v' = (73000 - 12000) / (98000 - 12000) * (1-0) + 0 = 61000 / 86000 = 0.716

2. Z-score Normalization

v' = (v - mean_A) / stdev_A

Example: μ = 54,000, σ = 16,000. For v = $73,000:

v' = (73000 - 54000) / 16000 = 19000/16000 = 1.225

3. Normalization by Decimal Scaling

v' = v / 10^j where j is the smallest integer such that Max(|v'|) < 1

Example: if values range from −986 to 917, the maximum absolute value is 986, so j = 3 (since 986/1000 = 0.986 < 1). A value of −986 normalizes to −0.986.

When to use which

MethodBest for
Min-MaxKnown, bounded min/max; preserves relationships exactly, but sensitive to new out-of-range values
Z-scoreData with unknown bounds or outliers; centers data at mean 0
Decimal scalingQuick, simple rescaling when only the order of magnitude matters

All three are used before distance-based algorithms (k-NN, k-Means, neural networks) so that, e.g., "income in dollars" does not swamp "age in years" purely due to differing scales.

✱B.17 Explain Data Discretization methods with a worked equal-frequency binning example. 10M

Discretization divides the range of a continuous attribute into intervals, replacing actual data values with interval labels — reducing data size and preparing data for algorithms (like many classifiers) that require categorical input.

Typical methods (all can be applied recursively)

Simple binning: Equal-width vs Equal-depth

Equal-width: divides the range into N intervals of size W = (B−A)/N, where A, B are the min/max. Simple, but outliers and skew distort the bins.

Worked example

Sorted price data: 4, 8, 9, 15, 21, 21, 24, 25, 26, 28, 29, 34 (n=12, N=3 bins)

Clustering-based discretization (e.g., k-Means on the 1-D values) typically produces even better-quality bins than either simple method because it groups by natural density rather than a fixed rule, at the cost of extra computation.

✱B.20 Explain the methods used to improve the efficiency of the Apriori algorithm. 5M

The naive Apriori algorithm re-scans the full database at every level and can generate a huge number of candidates, so several optimizations are commonly used together.

MethodHow it helps
Hash-based itemset countingWhile generating C1/C2, hash k-itemsets into buckets; any bucket whose count is below min_sup means every itemset hashed there is guaranteed infrequent, so those candidates can be dropped from C(k+1) before even counting
Transaction reductionA transaction containing no frequent k-itemset can never contain a frequent (k+1)-itemset, so it is removed from consideration in later passes
PartitioningSplit the database into n partitions; any itemset frequent in the whole DB must be locally frequent in at least one partition, so partition-local frequent itemsets are a superset of the global candidates, found in just 2 scans
SamplingMine a random sample of the DB with a slightly lowered support threshold, then verify against the full DB
Dynamic itemset countingAdd new candidate itemsets into consideration only once all of their subsets are already estimated to be frequent, instead of waiting for strict level-wise passes

Structurally, candidate itemsets are also stored in a hash-tree (leaf nodes hold itemsets+counts, interior nodes hold a hash table) so that, given a transaction, a subset function can quickly find all candidates it contains rather than testing every candidate against every transaction linearly. Together these techniques reduce both the number of database scans and the number of candidates generated — the two dominant costs of Apriori.

Unit 2 — Multilevel & Multidimensional Associations
✱B.25 Explain Multilevel Association Rule mining and the three approaches to setting support thresholds. 5M

Items in real transactional data naturally form concept hierarchies (e.g., "Skim Milk" → "2% Milk" → "Milk" as a general category), and multilevel association rules mine patterns at multiple levels of this hierarchy simultaneously.

Concept Hierarchy for Multilevel Mining
ApproachRuleTrade-off
Uniform SupportSame min-support threshold applied at every level of the hierarchySimple, but if set too high, misses meaningful low-level associations; if too low, generates too many uninteresting high-level rules
Reduced SupportLower min-support at deeper (more specific) levelsBetter captures rare but meaningful specific-item patterns; needs a search strategy (level-by-level independence, level-cross filtering by single item, or by k-itemset) to remain efficient
Group-based SupportDomain-expert-set threshold per item/group, independent of hierarchy levelLets analysts deliberately focus on commercially important but low-frequency groups (e.g., electronics), at the cost of requiring manual tuning

The core justification for reduced/group-based support is that items lower in a concept hierarchy are naturally rarer (Skim Milk sells less than "Milk" overall), so a single uniform threshold systematically under-represents specific-level patterns unless deliberately relaxed for them.

✱B.26 Explain Multidimensional Association Rules, distinguishing inter-dimension and hybrid-dimension rules. 5M

A single-dimensional association rule involves only one predicate repeated (e.g., buys(X,"milk") ⇒ buys(X,"bread")). A multidimensional rule involves two or more distinct predicates/dimensions.

Rule TypeDefinitionExample
Inter-dimension ruleNo repeated predicate; each dimension appears onceage(X,"19-25") ∧ occupation(X,"student") ⇒ buys(X,"coke")
Hybrid-dimension ruleContains a repeated predicateage(X,"19-25") ∧ buys(X,"popcorn") ⇒ buys(X,"coke")

Categorical vs Quantitative attributes

Categorical attributes have a finite set of unordered values (handled with a data-cube style approach, counting combinations directly). Quantitative attributes are numeric with implicit ordering and must first be discretized before mining, via static discretization (predefined ranges, decided once) or dynamic discretization (ranges adapted based on data distribution, clustering, or gradient-based search).

Techniques for mining multidimensional rules over quantitative attributes typically use a grid-based approach: the quantitative attribute space is partitioned into a grid of cells, support/confidence is computed for combinations of cells (candidate ranges), and adjacent cells may be merged to find the ranges that yield the strongest rules — conceptually similar to how discretization is used more generally in preprocessing.

Unit 3 — Bayesian Classification
✱B.27 State and derive Bayes' Theorem; explain prior, likelihood, posterior and evidence with a worked example. 10M

Bayes' Theorem relates the conditional probability of a hypothesis H given evidence X to the reverse conditional probability, and is the mathematical foundation of Bayesian classification:

P(H|X) = P(X|H) * P(H) / P(X)
TermMeaning
P(H)Prior probability — initial belief in H before seeing evidence
P(X|H)Likelihood — probability of observing evidence X given H is true
P(X)Evidence — total (marginal) probability of observing X, over all hypotheses
P(H|X)Posterior probability — updated belief in H after observing X

Informally: posterior = (likelihood × prior) / evidence. Classification then predicts that X belongs to the class Cᾝ for which P(Cᾝ|X) is highest among all classes (Maximum A Posteriori, MAP).

Worked example: defective cars

Companies B1, B2, B3 produce 30%, 45%, 25% of cars; 2%, 3%, 2% of their respective output is defective. Given a defective car, find P(Bᾑ | Defective) for each company.

CompanyP(Bᾑ)P(D|Bᾑ)P(Bᾑ)×P(D|Bᾑ)P(Bᾑ|D) = ratio/total
B10.300.020.00600.0060/0.0245 = 0.245
B20.450.030.01350.0135/0.0245 = 0.551
B30.250.020.00500.0050/0.0245 = 0.204

Total P(D) = 0.0060+0.0135+0.0050 = 0.0245. So a defective car is most likely (55.1%) to have come from company B2 — note this simply reflects that B2 produces the most cars and has the highest defect rate, illustrating how Bayes' theorem combines prior production share with likelihood of defect into one posterior belief.

100 e-mails -> 30 spam, 70 desired Spam containing 'offer' = 80% of 30 = 24 Desired containing 'offer' = 10% of 70 = 7 Total containing 'offer' = 24 + 7 = 31

✱B.29 Solve using Bayes' Theorem: probability a patient who tests positive actually has the disease. 10M

Given: a diagnostic test is 99% accurate; 60% of all people (prevalence) actually have the disease (Covid-19, per the slide example). Find P(Disease | Positive test).

Step 1: Define events

A1 = Has disease, P(A1)=0.6; A2 = No disease, P(A2)=0.4; P = tests Positive. Accuracy 99% means P(Positive|Has disease)=0.99 and P(Positive|No disease) = 1−0.99 = 0.01 (false-positive rate).

Step 2: Apply Bayes' Theorem

EventP(Aᾑ)P(P|Aᾑ)P(Aᾑ)×P(P|Aᾑ)P(Aᾑ|P)
Has disease (A1)0.60.990.5940.594/0.598 = 0.9933
No disease (A2)0.40.010.0040.004/0.598 = 0.0067

P(P) = 0.594 + 0.004 = 0.598. So P(Has disease | Positive) = 0.594/0.598 ≈ 99.33%.

Interpretation — why prevalence matters

This result is high mainly because the disease prevalence (60%) is unusually large; with a rare disease (say prevalence 1%), the same 99%-accurate test would give a far lower posterior probability due to a much larger relative pool of false positives — a classic illustration of the base-rate fallacy and a favourite "tricky" exam variant where students forget to weight by prior prevalence and just quote the test's raw accuracy.

✱B.30 Explain the Naive Bayes Classifier and apply it to classify X = (age≤30, income=medium, student=yes, credit_rating=fair). 10M

The Naïve Bayes Classifier applies Bayes' theorem with a simplifying (“naïve”) assumption: all attributes are conditionally independent given the class. This lets P(X|Cᾝ) be computed as a simple product instead of requiring a huge joint-probability table:

P(X|Ci) = P(x1|Ci) * P(x2|Ci) * ... * P(xn|Ci) Predict class Ci that maximizes P(X|Ci) * P(Ci) (since P(X) is constant across classes)

Step 1: Prior probabilities (buys_computer training data, 14 tuples)

P(buys_computer=yes) = 9/14 = 0.643 P(buys_computer=no) = 5/14 = 0.357

Step 2: Class-conditional probabilities for X = (age<=30, income=medium, student=yes, credit_rating=fair)

Attribute = valueP( . | yes)P( . | no)
age = “≤30”2/9 = 0.2223/5 = 0.600
income = “medium”4/9 = 0.4442/5 = 0.400
student = “yes”6/9 = 0.6671/5 = 0.200
credit_rating = “fair”6/9 = 0.6672/5 = 0.400

Step 3: Multiply out P(X|Ci)

P(X|yes) = 0.222 * 0.444 * 0.667 * 0.667 = 0.044 P(X|no) = 0.600 * 0.400 * 0.200 * 0.400 = 0.019

Step 4: Multiply by the prior and compare

P(X|yes) * P(yes) = 0.044 * 0.643 = 0.028 P(X|no) * P(no) = 0.019 * 0.357 = 0.007 0.028 > 0.007 => Predict: buys_computer = YES

Because 0.028 > 0.007, the classifier predicts X will buy a computer. This example is one of the most exam-favoured worked problems in the whole unit — practise reproducing the four conditional-probability lookups and the two final products without a calculator error.

✱B.31 Explain the Zero-Probability problem in Naive Bayes and how Laplacian correction resolves it. 5M

Naïve Bayes multiplies together every per-attribute conditional probability P(xᾠ|Cᾝ). If even one of these is zero (because that attribute value never appeared for that class in the training data), the entire product collapses to zero — regardless of how strongly the other attributes support that class. This is the zero-probability problem.

Worked example

Suppose a dataset of 1000 tuples has income=low (0 tuples), income=medium (990), income=high (10).

Uncorrected: P(income=low) = 0/1000 = 0 <-- would zero out any prediction involving low income Laplacian correction: add 1 to every count, and add (number of categories) to the denominator: P(income=low) = (0+1)/(1000+3) = 1/1003 P(income=medium) = (990+1)/1003 = 991/1003 P(income=high) = (10+1)/1003 = 11/1003

The corrected estimates remain very close to the uncorrected ones for the well-populated categories, but no probability is ever exactly zero, so a single unseen attribute-value combination can no longer wipe out an otherwise well-supported prediction. This smoothing technique is also called add-one smoothing and is applied uniformly across all categorical attribute values during Naïve Bayes training.

✱B.32 Explain the assumptions behind Naive Bayes, why it is called "naive", and its advantages/disadvantages. 10M

Why “Naïve”?

It is called “Naïve” because it makes the strong, often unrealistic simplifying assumption that the presence of one feature does not affect any other feature (conditional independence given the class); the “Bayes” part refers to its grounding in Bayes' Theorem.

Core assumptions

AssumptionExplanation
Feature independenceEach attribute contributes to the class prediction independently of all others
Continuous features normally distributedIf Ak is continuous-valued, P(xk|Ci) is computed from a Gaussian with class-specific mean μ and SD σ
Discrete features multinomially distributedCategorical attributes use simple frequency-ratio estimates
Features equally importantNo attribute is weighted more heavily than another a priori
No missing dataThe classifier assumes a complete, unbiased training set

Advantages

Easy and fast to implement, requires only a single pass to estimate all probabilities, performs comparably to decision trees and some neural networks on many real datasets, handles high-dimensional data (e.g., text classification) very well, and updates incrementally as new labelled examples arrive.

Disadvantages

Its core assumption — class-conditional independence — rarely holds exactly in practice (e.g., in medical data, “age” and “family history” are correlated, not independent), which causes some loss of accuracy. It also suffers from the zero-probability problem without Laplace smoothing.

When dependencies matter: Bayesian Belief Networks

When attribute dependencies are too important to ignore, Bayesian Belief Networks generalize Naïve Bayes by explicitly modelling a graph of conditional dependencies between attributes (rather than assuming full independence), trading Naïve Bayes' simplicity and speed for the ability to represent real inter-attribute relationships accurately.

Unit 2 — From Association Analysis to Correlation Analysis
✱B.33 Explain why Correlation Analysis is needed beyond Support-Confidence, and describe Lift, Chi-Square, and null-invariant measures with a worked example. 10M

The support-confidence framework used by Apriori/FP-Growth can produce misleading strong rules: a rule X → Y can have high confidence simply because Y is very frequent overall, regardless of any real relationship between X and Y. Correlation analysis supplements association analysis to filter out such spurious rules.

Worked example (AllElectronics, 10,000 transactions)

ItemCountBoth (game & video)
Computer games6,0004,000
Videos7,5004,000
Rule: game -> video Support(game,video) = 4000/10000 = 40% Confidence(game->video) = 4000/6000 = 66.7% (appears to be a strong rule) But baseline P(video) = 7500/10000 = 75%, which is HIGHER than 66.7%. So knowing a customer bought a game actually makes them LESS likely to buy video than a random customer -> game and video are negatively correlated.

Lift

Lift(A,B) = P(A U B) / (P(A) x P(B)) Lift(game,video) = 0.4 / (0.6 x 0.75) = 0.89 ( < 1 => negative correlation, confirming the paradox)

Chi-Square (χ²) Test

Builds a 2×2 contingency table of observed counts for (game,video), (game,¬video), (¬game,video), (¬game,¬video) and compares them against the counts expected under independence. A large χ² value indicates correlation; the sign of (observed−expected) in the (A,B) cell shows whether it is positive or negative.

Null-invariant measures: All-Confidence, Cosine, Kulczynski

Lift and χ² are both distorted by the count of “null transactions” (transactions containing neither item), which typically dominate large sparse datasets. Null-invariant measures do not change when this null count changes:

all_conf(A,B) = sup(A U B) / max(sup(A), sup(B)) cosine(A,B) = sup(A U B) / sqrt(sup(A) x sup(B)) Kulc(A,B) = 1/2 [ P(A|B) + P(B|A) ]

Because they are unaffected by null transactions, all-confidence, cosine and Kulczynski (often paired with the Imbalance Ratio to check if A and B occur with similar frequency) are generally preferred over lift and χ² for correlation analysis on large, sparse real-world transaction databases such as retail baskets.

Unit 3 — Supervised vs Unsupervised Learning
✱B.34 Explain Supervised and Unsupervised Learning in detail, with a comparison table and examples of algorithms from the syllabus. 10M

Machine learning algorithms are broadly divided into supervised and unsupervised learning, based on whether the training data carries a known output label.

Supervised Learning

The model is trained on labelled data — every example has both input features X and a known correct output Y (class label or numeric value) — and learns a function/mapping f: X → Y that generalizes to new, unseen inputs. Because ground truth is available, the model's predictions can be directly checked against the true labels during training and evaluation.

Unsupervised Learning

The model is given only unlabelled data (input features, no known output) and must discover hidden structure, groupings, or relationships on its own, without any “correct answer” to learn from.
